# 用户、套餐和权限

管理员可以在面板中管理用户和套餐。

常见功能：

- 创建用户。
- 设置用户到期时间。
- 设置流量额度。
- 设置最大规则数、端口数。
- 分配可用端口转发、隧道、转发链或转发组资源。
- 配置套餐和价格。
- 配置余额、兑换码、折扣码。
- 配置邀请返利，按套餐设置返利比例（见[邀请返利](./referrals.md)）。
- 配置邮件提醒或 Telegram 提醒。

## 新手建议

如果你只自己使用，可以先不用配置复杂套餐，只保留管理员账户和基础规则即可。

如果要开放给用户使用，建议先规划：

- 每个用户最多可以创建多少规则。
- 每个用户最多可以使用多少端口。
- 每个用户能使用哪些端口转发、隧道、转发链或转发组。
- 流量超额后如何处理。
- 到期前是否发送提醒。

## 权限分配

权限分配要遵循最小可用原则。

例如，一个用户只需要使用香港入口，就不要把所有端口转发和链路资源都分配给他。这样可以降低误操作风险，也方便后续统计和排查。

## 流量统计与重置

用户列表中的“流量使用”分为两项：

| 统计项 | 含义 |
| --- | --- |
| 套餐/分配 | 用户套餐或管理员分配额度内的已用流量，用于额度和超额状态判断 |
| 按量计费 | 按流量计费规则累计的使用量，便于单独核对计费流量 |

![用户列表分别展示套餐/分配流量和按量计费流量](./images/users-traffic.png)

管理员可在目标用户的“更多”菜单中选择“重置流量统计”。手动重置会把页面显示的套餐/分配流量和按量计费流量都从零重新统计，但不会撤销已经产生的扣费记录，也不会修改用户余额。

套餐的定时重置仍只重置套餐/分配流量，不会改变按量计费统计。需要同时重新统计两项时，应使用用户列表中的手动重置操作。

### 用户流量历史

管理员在目标用户的“更多”菜单中选择 **“流量历史”**，可以看这个用户最近 30 / 90 天每天的上传 / 下载（柱状图）、合计，以及这段时间用量最多的 10 条规则（转发组成员的流量记在模板规则上，已删除的规则显示「已删除的规则 #ID」）。

- 上传 = 入站（客户端发出的字节），下载 = 出站（回给客户端的字节），和仪表盘「流量走势」同一口径，**不含计费倍率**，也不受“重置流量统计”影响。
- 数据来自已有的规则流量统计，不新增任何采集：面板每 10 分钟把最近 3 天的 30 分钟流量桶按「用户 × 规则 × 天」汇总一遍（天按计费时区切），日记录保留 100 天。原始流量桶只留 72 小时，所以**功能上线之前的日子没有数据**，对话框底部会写明从哪天开始有记录。
- 日记录跟着面板备份 / 迁移走（完整备份才带，精简备份和其他历史数据一样不带）。

## 库存与每账号规则上限

在「套餐管理」里编辑订阅套餐时可以设「库存总量」，在「流量计费」页编辑按量计费资源时可以设「账号库存」和「每账号规则上限」。三项都是 `0` 表示不限，商店里显示 `∞`；限量的显示剩余数量，卖完的商品**照常展示**、显示「已售罄」，只是不能下单。管理页上同时显示已售（已占用）和剩余。补货时把总量加大，而不是把剩余数量填进总量。

**订阅套餐**按份数卖：

- 新购（余额购买、在线支付）、管理员分配、兑换码兑换各占 1 份。在线支付的待支付订单**下单时就占**，免得最后一份被几个人同时付款。
- 续费不占库存，售罄的套餐照样能续费。
- 没付款的订单关闭（取消、过期、创建失败）后退回那一份；已售出的订阅到期或取消**不退回**。
- 付了款却已经没货（例如老版本创建、下单时没占库存的订单）：不开通，实付金额转入余额，订单备注「已转入余额」。
- 启用这项之前卖出去的不追溯计入；不限库存的套餐也会累计销量，改成限量时在这个数上设总量。

**按量计费资源**按账号占席位：

- 同一账号在同一资源上只占 1 份，不管建了多少条规则。转发组、线路组自动展开出的子规则不算；停用的规则仍占着；删掉他在这个资源上的**全部逻辑规则**后才让出。
- 「每账号规则上限」限制一个账号在这个资源上能建几条逻辑规则。库存满了以后，已经占着席位的账号仍可在自己的上限内继续建规则。
- 新建规则、把规则改给别的账号、换到另一个资源、从待删除恢复，都会重新校验。调低库存或上限不会删除已有规则，只拦新增。
- 一条规则同时命中多个计费配置时，按「转发组 → 隧道 → 主机」的优先级占其中一个的库存，和扣费用的是同一个。管理员自己的规则不计费，也不占席位。

库存校验在数据库事务里实时完成，不读展示缓存：套餐用一条带条件的更新语句占额，按量资源先锁住计费配置再数占用。SQLite、MySQL、PostgreSQL 下都一样，多个面板实例共用一个库时并发下单也不会超售。

## 账单流水导出 Excel

账单可以导出成带格式的 Excel（`.xlsx`）文件：

- **管理员**：「账单与兑换 › 账单流水」右上角的「导出全部」。右边选了某个用户时按钮变成「导出该用户」，只导出这个人的记录。是否包含已取消的订阅跟着「查看已取消」走。
- **普通用户**：「钱包 › 账单流水」右上角的「导出 Excel」，只能导出自己的全部记录（服务端按登录的账号决定，改请求参数也导不出别人的）。

一个文件三张表：**账单流水**（余额、支付订单、套餐记录合在一起，和页面上一致）、**余额流水**（每笔变动和变动后余额）、**支付订单**（含未支付的）。表头加粗、带底色并冻结，时间是北京时间的日期格式，金额是保留两位小数的数字，可以直接求和、筛选。以 `=` `+` `-` `@` 开头的文字（比如用户自己填的名字）按纯文字写入，不会被当成公式执行。

一次最多导出 50000 条记录，超出时会提示条数；管理员可以按用户分开导出。

## 删除未支付订单

「支付对接 › 订单记录」里，没付过款的订单（待支付、已过期、已取消、失败）可以单条删除，也可以勾选后「删除所选」，删除前会二次确认。**已支付、处理中、已完成的订单不能删**；收到过支付网关付款通知的失败订单（比如金额对不上被拒）也不能删，留着对账。

- 待支付订单占着的套餐库存、折扣码名额在删除时一并退回（和删除在同一个数据库事务里）。
- 删除后如果客户仍在收银台完成了付款，支付网关的回调到了找不到订单：面板保留了一条删除记录，金额、币种和支付渠道对得上就把**实付金额转入该用户的余额**（余额流水写明「订单已被管理员删除」），不再开通套餐；对不上的拒绝并记错误日志。同一笔回调重复到达只入账一次。测试订单不入余额。
- 删除记录保留 180 天，只在本面板的数据库里，不随备份迁移。

## 登录页的人机验证和 Telegram 登录

系统设置 › **注册与登录** 里管登录页的几样东西：

- **登录 / 注册人机验证**：默认开。注册、找回密码每次都要过一遍；登录只在同一账号连续输错 3 次（或这个账号从各处累计输错 10 次）以后才要。关掉后密码校验、登录失败限流和双重验证照旧。
- **人机验证方式**：**点击验证**（默认，点一下，浏览器在后台算一小段工作量证明）或**图片验证码**（看图填字符，混淆过；老浏览器、只走 HTTP 的环境里点击验证跑不起来时换这个）。登录、注册、忘记密码三处都按选中的方式画。服务端也只认这一种：另一种的答案一律算验证失败，另一种的挑战也不再发，不能绕过页面专挑好过的那种来刷。刚换了方式时，还开着旧页面的人提交会提示验证失败，刷新一下就好。
- **Telegram 登录**：默认开。关掉后登录页不再显示「Telegram 快捷登录」，机器人里的「网页登录」一次性链接、WebApp 里的自动登录、手机 App 的 Telegram 确认登录都会被拒绝，机器人回复「管理员已关闭 Telegram 登录」。只关登录这一件事：机器人本身、到期 / 流量 / 主机提醒、账号绑定和解绑、用 Telegram 收找回密码链接都照旧。

## 用户忘记密码

登录页密码框旁边有「忘记密码？」。用户填用户名或邮箱（开着人机验证时要先过一遍，方式和登录页一样），面板把一次性重置链接发到这个账号**已验证的邮箱**、**已绑定的 Telegram** 和 **已绑定的 Discord**（有哪个发哪个）。链接 30 分钟内有效、只能用一次；再申请一次，之前的链接全部作废。

设好新密码以后，这个账号所有设备上的登录和 API 令牌都会失效，要用新密码重新登录。双重验证和通行密钥不变：开了 2FA 的账号登录时照样要输验证码。

管理员需要先准备：

- 系统设置里填好**面板公开访问地址**：链接只用这个地址拼，不会用访问者请求里的域名；没填就不发。
- 至少一个能发出去的渠道：邮件（SMTP）、Telegram 机器人或 Discord 机器人。
- 系统设置 › 注册与登录 里的「登录页『忘记密码』」默认开着，不想开放自助找回就关掉。

为了不让别人拿这个功能试探「某个邮箱在不在面板上」，不管账号存不存在、有没有绑找回方式，页面回的都是同一句话。账号没有已验证邮箱、也没绑 Telegram / Discord 时收不到任何东西，用户需要**联系管理员**在用户管理里重置密码。停用的账号申请不到链接。同一个来源 IP 半小时最多申请 6 次，同一个账号一分钟 1 次、一小时 3 次。

每次发出链接、每次通过链接改密码，都会记进 监控 › 操作审计 和事件时间线。

## 进入用户后台

想看看某个用户眼里的面板是什么样子、帮他排查规则，可以在用户管理里点这个用户的「更多 › 进入后台」。面板会在**新标签页**里以这个用户的身份打开后台，顶上一直显示「正在以 某某 的身份查看」和「退出」；你原来的标签页还是管理员，不受影响。

- 只能进启用着的普通用户，不能进管理员账号。代入窗口里没有任何管理员权限。
- 一次最长 1 小时，到点自动结束；点「退出」、管理员自己退出登录或改了密码、目标用户被停用，都会立刻结束。结束后那个标签页只显示「已退出用户后台」，不会变回管理员。
- 代入时不能改这个用户的账号安全设置（密码、邮箱、双重验证、通行密钥、登录设备、Telegram / Google / Discord 绑定），也不能替他付款、充值、兑换或开关自动续费。这些请让用户本人操作，或回到管理员窗口在用户管理里处理。
- 用户本人的登录不受影响，他的「已登录设备」里也不会多出一台。
- 每次进入都会记进操作审计（哪个管理员、进了谁、从哪个 IP）和事件时间线；代入期间做的修改在操作审计里记在管理员名下，来源写「代入用户后台」并标明是以谁的身份做的。
- API 令牌不能发起进入用户后台；手机 App 里没有这一项（App 没有新标签页）。
