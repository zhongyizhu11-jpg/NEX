# 教程概览

NEX 用于管理多台 Linux 服务器上的转发资源、业务规则、用户权限、流量和延迟数据。当前版本：面板 2.3.266 / Agent 2.2.181 / Android APP 2.3.97。

| 步骤 | 文档 | 说明 |
| --- | --- | --- |
| 1 | [快速开始](./quick-start.md) | 最小化部署体验 |
| 2 | [部署前准备](./preparation.md) | 服务器环境和依赖检查 |
| 3 | [部署面板](./deploy-panel.md) | Docker / 手动安装面板（默认端口 9810） |

| 7 | [创建转发规则](./rules.md) | 为用户配置访问端口、协议和目标地址 |

## 基本流程

```text
部署面板 → 初始化数据库 → 创建 Agent Token → 安装 Agent
→ 创建链路资源 → 添加转发规则 → 检查运行状态与链路测试
```

## 资源模型

| 资源 | 说明 |
| --- | --- |
| 主机（Agent） | 受控 Linux 服务器，负责执行规则下发，支持在线状态和资源占用监控 |
| 端口转发 | 单跳直接端口映射 |
| 隧道 | GOST / NEX V1 / NEX V2 / Nginx Stream，跨主机加密或混淆中转 |
| 转发链 | 多个隧道组成的固定多跳路径 |
| 转发组 | 多个链路的负载均衡 / 故障转移集合 |
| 入口组 | 多个入口地址的聚合，支持 DDNS 故障转移 |
| 出口组 | 多个出口地址的聚合 |
| 转发规则 | 面向用户的访问配置：端口、协议、目标链路 |
| 服务 | 独立延迟探测服务，附带图表 |
| 插件 | 扩展功能，支持 Agent 动作和动态资源界面 |

## 常用词 {#glossary}

界面上反复出现的几个词，各用一句话说清楚：

| 词 | 意思 |
| --- | --- |
| 入口 / 源端口 | 用户连进来的那台机器和端口。「源端口」留空时面板随机分配一个 |
| 目标地址 / 目标端口 | 流量最终要去的地方，也就是你要转发到的服务 |
| 出口 | 隧道或转发链的最后一台机器，由它把流量交给目标 |
| 中转 | 入口和出口之间经过的机器 |
| Agent | 装在每台服务器上的小程序，负责按面板的配置真正去转发流量 |
| 主线路 / 备用线路 | 开了[主备线路](./failover.md)的规则：平时走主线路，主线路出问题时自动换到备用线路 |
| 探测地址 | 判断一条线路通不通时实际去连的地址，默认就是线路地址本身 |
| 内核转发 / 用户态转发 | iptables、nftables 在系统内核里转发，最快；gost、realm 这类是一个程序在转发，功能更多 |

## 常用页面

| 页面 | 用途 |
| --- | --- |

| 用户管理 | 管理用户、权限、额度和到期时间 |
| 系统设置 | 配置公开地址、通知、升级和备份 |
| 插件管理 | 安装插件并管理插件权限、Agent 同步和动态资源 |
