# 落地池

落地池是**节点池**的一种用途（2.3.500 起）：几台机器开**同一份落地**，协议、端口、密钥、用户都一样。订阅里整个池**只有一条**，客户端拿到的这一份配置连哪台都能通。

| | 中转池 | 落地池 |
| --- | --- | --- |
| 用来做什么 | 线路里的一层中转，面板在几台里挑 | 落地：几台开一样的入站，订阅里一条 |
| 池里加一台 | 用到它的线路多出一条路径 | 那台自动开上这份落地，线路多出一条路径 |
| 池里去掉一台 | 线路少一条路径 | 那台的入站自动收掉 |

2.3.499 以前的「通用」池，现在算中转池。

## 新建

**链路管理 → 更多 → 节点池 → 新建 → 落地池**（只开一台的落地节点不用建池，到「订阅管理 › 新建 › 在我的机器上开一个」；那个「新建」菜单里管理员也能看到一条「几台开同一份（落地池）」，点了到这里）：

1. 起个名字，加几台机器（最多 8 台）。
2. 选协议和端口。第一版支持：
   - **VLESS + REALITY**（默认，建议开 Vision 流控）
   - **VMess / VLESS 不加密**（可以选 WebSocket、gRPC、HTTPUpgrade 这些传输）
   - **Shadowsocks**（含 SS2022）
   - **Snell v5 / v6**
   - **SOCKS5**

   要证书的 TLS 不在里面：证书是按机器、按域名签的，几台共用一份配置对不上。

   **Mieru 也不在里面**：它不跑在 sing-box 上，而是每台机器一个 mita（见下面「Mieru 落地」），用户名要在整台机器上唯一、流量按用户记，几台共用一份凭据的落地池对不上这两条。要 Mieru 就在单台机器上开（「订阅管理 › 新建 › 在我的机器上开一个」）。
3. 多用户协议（VLESS、VMess、SOCKS5）可以加几个用户，每人一份凭据，每台都一样。
4. 保存。凭据和 REALITY 密钥由面板生成，每台机器上开一个一模一样的入站。

某台的端口被占了，面板给那台换一个空闲端口，卡片上写「换了端口」。订阅里还是一条，走中转不受影响，因为面板知道每台在哪个端口。

## 订阅里是什么样

- **走中转（默认）**：订阅里只有中转那一条，凭据是池的。转发或线路的落地选这个池，面板在几台里分，坏了切走。
- **直连（可选）**：给池设一个**直连域名**，订阅里多一条直连。面板只把在线的机器解析到这个域名，机器离线了就把它从解析里摘掉。要先在 **系统设置 → DDNS** 配好 DNS 服务商。开了直连域名，每台必须同一个端口：端口被占的那台不开。
  - 「直连域名」右边的 **自动**：在 DDNS 管着的主域名下起一个没被别的池用过的名字，比如 `hk-3f41.example.com`（池名能拼成英文就用池名，中文名用池里机器的地区）。阿里云、腾讯云用设置里填的主域名；Cloudflare、华为云按 Zone ID 去查，没填 Zone ID 时账号下只有一个域名才能自动；Webhook 方式不知道主域名，自己填一个完整域名。
  - 直连域名**只有管理员能设、能改**（2.3.501 起）：面板拿系统的 DNS 服务商替它写解析。普通用户的落地池能看到管理员设的域名，改不了。

「我的节点」里一个池就是一行，点「3/3 台」看每台开在哪个端口。成员机上的入站是只读的：改协议、换密钥、删机器，都到节点池里改，每台一起改。

## 转发和线路怎么用它

- **转发规则**：目标地址旁边「选我的节点」里，落地池写成「池 · 名字 · N 台」。选了它保存：
  - gost、realm、socat、nginx 转发（管理员的端口转发、隧道转发、端口转发资源）会自动做成一个线路组，一台一条路径，新连接按负载在几台里分，坏了自动跳过。
  - iptables / nftables，以及普通用户的普通端口转发，只能指向一台：指向池里排在前面、在线的那台，那台坏了换下一台。
- **线路**：落地那一格的菜单里有「落地池」一组。选了它，这条线路展开成一台一条路径，线路详情里写「池名 · 机器」。落地下面的「N 个落地」选这几台怎么用：主备（默认），或者按负载分、轮流、随机、按访客固定（2.3.501 起，见[多落地](./failover.md#landings)）。

池从一台变成两台以上时，目标是这个池的普通转发会自动补成线路组。

## 分享

管理员在「我的节点」里把落地池分享给别人：

- VLESS、VMess、SOCKS5：给对方**单独发一份凭据**，每台机器都加上。取消分享就收回，对方手上那份立刻失效。
- Shadowsocks、Snell：只能共用池主人的那一份，和单台入站一样。

## 换密钥、删池

- **换密钥**：节点池弹窗里的「换密钥」，每台一起换，客户端要重新拉订阅。
- **删池 / 改回中转**：还有转发的目标是这个池时不让删，会列出是哪几条。先把它们的目标换掉再删。删了以后，每台机器上的入站和订阅里那一条一起收掉。

## Mieru 落地（单台）

Mieru 不在落地池里，但单台的落地节点可以选它。和别的协议不一样的地方：

- **运行时是 mita，不是 sing-box**：sing-box 没有 Mieru 服务端。面板把这台机器上所有 Mieru 入站合成一份 mita 配置，Agent 装一个钉死版本的 mita（`forwardx-mita` 服务，systemd / OpenRC / OpenWrt 都支持），只在配置变了时才重启它。机器上另装的 mita（`mita.service`、`/etc/mita`）不是 NEX 的，Agent 不碰。
- **需要 Agent 2.2.253 以上**：Agent 旧的机器上，Mieru 入站照常保存，但不下发，行上写「需要升级 Agent」。升级 Agent 后一分钟内自动开起来。
- **承载**：TCP、UDP，或者两个都开（同一个端口 TCP、UDP 各听一份）。
- **端口段**：可以填一个终点，比如 27010–27019，mita 整段都听，客户端每条连接随便挑一个（最多 100 个端口）。段里每个端口都要没被别的转发、隧道、落地占用。经中转时只用起点那一个。
- **每人一份凭据**：和 VLESS 一样能加几份凭据、分享给别人时单独发一份。用户名是面板生成的随机串（`nex` 开头）。
- **不支持分流**：分流是 sing-box 的路由做的，mita 没有这一层。

mita 的用户表是整台机器共用的：同一台机器上两个 Mieru 入站，A 的凭据连 B 的端口也能通。所以流量**按凭据**记（mita 自己按用户计数），不按端口：每份凭据单独有用量，加起来记到入站的端口用量和归属用户的套餐上。mita 重启时，上次上报之后那一小段（最多一分钟）记不上。
