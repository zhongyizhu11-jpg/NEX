# 工单

用户遇到问题时可以在面板里提交工单，管理员在「工单管理」里集中处理和回复。工单只支持纯文本，不能上传附件。

## 工单状态

| 状态 | 什么时候 |
| --- | --- |
| 待处理 | 刚提交、用户补充了回复、或者工单被重新打开，等管理员处理 |
| 已回复 | 管理员回复过了，等用户回复 |
| 已关闭 | 用户或管理员关闭了工单 |

已关闭的工单不能直接回复，要先点「重新打开」，重新打开后回到「待处理」。

## 用户：提交和跟进工单

进入：

```text
左侧导航 -> 工单
```

1. 点右上角「新建工单」，填写标题、选择优先级、写清问题描述，然后提交。
   - 标题只能一行，最多 128 个字。
   - 问题描述最多 5000 个字，可以换行。
   - 优先级分低、中、高三档，管理员会优先处理高优先级的工单。
2. 提交后工单出现在左边列表里，点开就能看到对话。管理员回复后，列表里这一张前面会出现一个小圆点，状态变成「已回复」。
3. 在对话下面的输入框里可以继续补充说明，按「发送」或 `Ctrl / ⌘ + Enter` 发送。
4. 问题解决后可以点「关闭工单」。之后如果又有问题，点「重新打开」即可继续。

打开的对话每 10 秒自动刷新一次，列表每 30 秒刷新一次，不用手动刷新页面。手机上先看列表，点开一张后进入对话，点「返回工单列表」回到列表。

::: tip
描述问题时尽量带上：哪条规则或哪台机器、从什么时候开始、看到了什么报错。管理员看到的信息越完整，处理得越快。
:::

### 频率限制

为了防止刷屏，每个用户每小时最多新建 5 张工单，每 10 分钟最多回复 30 条（所有工单合计），同时最多有 10 张没关闭的工单（关掉已经解决的才能再提新的）。超过时会提示稍后再试。计数按数据库里的记录算，面板重启不会清零。管理员不受这些限制。

## 管理员：处理工单

### 开放 / 关闭工单

「工单管理」页右上角的「开放工单」开关是工单功能的总开关，切换后立即生效：

- 关闭后，普通用户侧边栏不再显示「工单」，也不能新建工单或回复已有工单；之前提交的工单仍然能查看。
- 管理员不受影响，照常在「工单管理」里查看、回复和关闭工单。


进入：

```text
左侧导航 -> 工单管理
```

- 侧栏「工单管理」后面的数字是当前「待处理」的工单数，每分钟刷新一次。
- 列表默认只看未关闭的工单，排序是：待处理的在最前，其次已回复、已关闭；同一状态里优先级高的在前，再按最后一条消息的时间从新到旧。
- 可以按状态、优先级筛选，也可以搜索标题、用户名，或者输入 `#编号` 直接找某一张。
- 点开工单后可以回复、关闭或重新打开。管理员的回复在用户那边统一显示为「客服」，用户看不到是哪位管理员回复的。
- 用户被删除后，他的工单仍然保留，用户名显示为「已删除用户」。

### 隐藏工单入口

不需要工单功能时，可以在：

```text
系统设置 -> 系统配置 -> 左侧导航栏菜单展示设置 -> 管理菜单开关
```

取消勾选「工单」。关闭后用户的「工单」和管理员的「工单管理」都不再出现在侧栏里，已有的工单数据不会删除。

## 通知

| 事件 | 谁会收到 | Telegram | 邮件 | Webhook |
| --- | --- | :---: | :---: | :---: |
| 用户新建工单 | 管理员 | ✓ | - | ✓（`ticket.created`） |
| 用户回复工单 | 管理员 | ✓ | - | ✓（`ticket.replied`） |
| 管理员回复工单 | 工单的提交人 | ✓ | ✓ | - |

- **Telegram**：需要面板已启用机器人，且收件人已经绑定 Telegram。每个人可以在机器人里发送 `/notify`，在「通知设置」里单独关掉「工单消息」，只影响自己，不影响其他人。消息里会附上面板链接（需要在系统设置里填写面板公开地址）。
- **邮件**：需要在「系统设置 -> 邮箱设置」里启用 SMTP，并且用户的邮箱已经验证过。没有验证过邮箱的用户不会收到邮件。
- **Webhook**：在「系统设置 -> Webhook」里勾选「工单」分类即可推送新建和回复事件。新装面板默认全部分类都开；升级前就保存过 Webhook 分类的面板，需要手动勾上「工单」。

通知发送失败不会影响工单本身的提交和回复，失败原因记在面板日志里（关键字 `[Ticket]`）。

## 备份和迁移

工单和工单消息会跟着面板备份、面板迁移、数据库切换一起带走。
