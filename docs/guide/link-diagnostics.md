# 链路诊断（一键诊断）

> 面板 2.3.444 起 / 主机上的检查需要 Agent 2.2.225

规则、隧道、转发链出问题时，点卡片上的 **诊断**，对话框默认打开 **一键诊断** 页：面板把这条链路从配置到目标拆成一张清单，逐项给出 **通过 / 警告 / 失败 / 跳过 / 等待**，每项一句结论和一句「怎么修」。最上面是总评和 **最可能的原因**——直接从那一项查起就行。

原来那种一段段测延迟的诊断还在，切到 **延迟测试** 页，用法不变。

## 怎么用

1. 在规则列表（卡片右上角 ··· 或表格行的「诊断」）、隧道列表、转发链列表里点 **诊断**。
2. 打开就开始检查。面板这边能判断的项马上出结果；需要到主机上看的项先显示 **等待**，主机回报后（一般十几秒内）逐项更新，页面每 2 秒刷新一次。
3. 点一行展开，看修复建议和原始输出（命令输出、解析到的地址等）。
4. **复制结果** 把整张清单复制成纯文本，发工单或贴给管理员时直接粘贴。

普通用户可以诊断自己的规则、隧道和转发链；别人（比如管理员）的主机上的原始输出只有管理员能看到，结论照常显示。

## 状态的意思

| 状态 | 意思 |
|------|------|
| 通过 | 这一项没问题 |
| 警告 | 可能有问题，但不一定是故障原因（比如防火墙里没看到放行规则，但可能在别处放行了） |
| 失败 | 确定有问题，通常就是不通的原因 |
| 跳过 | 这一项不适用，或没条件检查（主机离线、目标是 IP 不用解析等） |
| 等待 | 在等主机回报 |
| 需要升级 Agent | 这台主机的 Agent 低于 2.2.225，主机上的检查没做；在主机页点「升级 Agent」后重新诊断。其余项照常检查 |

**最可能的原因** 按 配置 → 主机 → 入口 → 链路 → 目标 的顺序，取第一项失败（没有失败就取第一项警告）。越靠前越根本：规则被停用了，端口当然不在听、目标当然连不上，先处理前面的。

## 检查项

### 配置（面板判断）

| 检查 | 怎么判 | 不通过时怎么办 |
|------|--------|----------------|
| 规则 / 隧道 / 转发链已启用 | 开关、是否在删除中、是否被隧道或转发组连带停用、是否被系统停用（例如端口冲突） | 按提示恢复上级资源或手动打开 |
| 目标地址 | 目标地址不为空，目标端口在 1-65535 | 编辑规则补上 |
| 入口端口在允许范围内 | 主机端口范围 / 白名单、隧道端口范围、套餐端口段 | 换范围内的端口，或请管理员放宽 |
| 转发方式可用 | 管理员没在「转发协议」里关掉这种方式；账户允许使用它 | 换一种转发方式，或请管理员授权 |
| 账户状态 | 账户启用、没到期、转发没被暂停（3 天内到期给警告） | 续期 / 充值 / 请管理员启用 |
| 流量额度 | 已用 ≥ 额度为失败，≥ 90% 为警告 | 重置流量或调高额度 |
| 规则数量配额 | 规则数超过套餐上限给警告 | 删掉不用的规则或升级套餐 |

管理员账户不受套餐、流量限制，这几项直接通过。

### 主机（面板判断）

链路上每台主机一项（入口、中转、出口）：

- **离线** → 失败。到那台主机上看 `systemctl status forwardx-agent`，以及面板地址、网络是否变了。
- **NEX 隧道上 FXP 握不上当前协议**（没装或太旧）→ 失败，升级 Agent 会一并装新 FXP。
- **Agent 低于 2.2.225** → 警告，主机上的那几项检查会显示「需要升级 Agent」。

### 入口

| 检查 | 谁来测 | 怎么判 |
|------|--------|--------|
| 规则在入口主机上运行 | 面板 | Agent 上报的运行状态；没跑为失败，还没报过为警告 |
| 端口没被别的规则占用 | 面板 | 和保存规则时同一套端口占用检查（规则、隧道、入站、换隧道后的临时桥接） |
| 入口域名 / 主机 DDNS | 面板 | 从面板解析域名，看是不是入口主机现在的 IP；解析失败为失败，解析到别的地址为警告（换 IP 后还没同步，或套了 CDN） |
| 端口在监听 | 主机 | 读 `/proc/net/tcp(6)`、`/proc/net/udp(6)`，看端口和协议（tcp / udp / 都要）有没有在听 |
| 内核转发规则 | 主机 | iptables / nftables 类型的规则不在本机监听，改为在 `nft list ruleset` / `iptables-save -t nat` 里找这个端口 |
| 防火墙放行端口 | 主机 | 看 ufw、firewalld、iptables（INPUT，内核转发看 FORWARD）、nftables 有没有挡住这个端口；明确拒绝为失败，默认丢包且没看到放行为警告。面板的「地区规则 / IP 封禁」生效时会在细节里注明。**云厂商安全组看不到，需要自己确认** |
| 本机连得上端口 | 主机 | 从主机连 `127.0.0.1:端口`（监听在具体地址时连那个地址），再连自己的公网 IP；本机都连不上为失败，只有公网 IP 不通为警告（NAT 机器常见） |
| 转发进程在运行 | 主机 | realm / socat 看对应的 systemd 服务，gost 看 `forwardx-runtime`，nginx 看 `forwardx-nginx`，NEX 隧道看 FXP 进程 |

### 链路（隧道、转发链）

- **隧道在中转 / 出口上运行**：面板记录的每台主机的隧道运行状态。
- **隧道端口在监听、防火墙放行**：在每台中转和出口主机上检查隧道监听端口。
- **每一段下一跳**：从每台主机 TCP 连下一跳的地址和端口（地址选法和延迟探测一致：连接地址 → 内网地址 → 入口地址）。连不上为失败，3 次里有失败为警告。NEX v2（WireGuard，UDP）不做 TCP 测试，看「延迟测试」。
- **转发链**：每台成员主机上的子规则的运行状态、监听，以及链上每一段的连通。

### 目标

| 检查 | 谁来测 | 怎么判 |
|------|--------|--------|
| 目标地址 | 面板 | IP 是公网地址为通过；内网 / 保留 / 回环地址为警告（除非它正好是面板里某台主机的地址）；域名从面板解析不了为警告——面板和主机的 DNS 可能不同，以主机上的解析结果为准 |
| DNS 解析 | 主机 | 在拨号的那台主机上用系统解析器分别查 IPv4、IPv6，都查不到为失败；细节里带 `/etc/resolv.conf` 的 nameserver |
| 连得上目标 | 主机 | 在拨目标的那台主机上（直连规则是入口，隧道规则是出口，转发链是最后一跳）TCP 连 3 次，给出最快的延迟。UDP 规则只能尽力而为：收到「端口不可达」为失败，没回包为跳过（很多 UDP 服务不回空包） |

主机上的整组检查最多 30 秒，超时的项显示为警告。

## 常见结论怎么处理

- **端口没有程序在听**：先看同一组里的「运行状态」和「转发进程」。端口可能被别的程序占了（`ss -ltnup | grep :端口`），或者转发程序起不来（`journalctl -u forwardx-agent -n 100`）。
- **本机通、外面不通**：多半是防火墙或云安全组。先看「防火墙放行端口」那一项，再去云控制台放行端口。
- **连不上下一跳 / 目标，连接超时**：对端防火墙丢包或路由不通；**拒绝连接**：对端端口没开。
- **入口域名解析到别的 IP**：主机换过 IP 而记录还没更新，等 DDNS 同步或 TTL 过期；套了 CDN 时这是正常的。

还是查不出来时，点 **复制结果**，连同 [常见问题排查](./troubleshooting.md#收集诊断信息) 里的诊断信息一起发工单。
