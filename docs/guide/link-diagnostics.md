# 链路诊断（一键诊断）

> 面板 2.3.445 起 / 主机上的检查需要 Agent 2.2.226

规则、隧道、转发链出问题时，点卡片上的 **诊断**。三处是同一个对话框，页签和底部按钮都一样（2.3.506 起转发链也一样）：

| 页签 | 内容 |
|------|------|
| 延迟测试 | 打开就是这一页，自动测一次：沿着这条链一段段测延迟，下面一行写上次几点测的、通没通 |
| 一键诊断 | 切过去才开始：面板把这条链路从配置到目标拆成一张清单，逐项给出 **通过 / 警告 / 失败 / 跳过 / 等待**，每项一句结论和一句「怎么修」。最上面是总评和 **最可能的原因**——直接从那一项查起就行 |
| 延迟记录 | 最近的延迟曲线、稳定性统计、近 30 天的色块 |
| 连接 / 连接监控 | 规则此刻的连接；NEX 隧道逐跳的连接（管理员） |

底部一排：**导出故障包**、**查看拓扑**；隧道多一个 **测带宽**，打开「网络测试 › iperf3 对拉」并选好这条隧道，一段一段测（和线路详情里的「逐段测带宽」是同一种测法、同一种结果）。

## 怎么用

1. 在规则列表（卡片右上角 ··· 或表格行的「诊断」）、隧道列表、转发链列表里点 **诊断**，切到 **一键诊断**。
2. 切过去就开始检查。面板这边能判断的项马上出结果；需要到主机上看的项先显示 **等待**，主机回报后（一般十几秒内）逐项更新，页面每 2 秒刷新一次。
3. 点一行展开，看修复建议和原始输出（命令输出、解析到的地址等）。
4. **复制结果** 把整张清单复制成纯文本，发工单或贴给管理员时直接粘贴。

普通用户可以诊断自己的规则、隧道和转发链；别人（比如管理员）的主机上的原始输出只有管理员能看到，结论照常显示。

## 状态的意思

| 状态 | 意思 |
|------|------|
| 通过 | 这一项没问题 |
| 警告 | 可能有问题，但不一定是故障原因（比如防火墙里没看到放行规则，但可能在别处放行了） |
| 失败 | 确定有问题，通常就是不通的原因 |
| 跳过 | 这一项不适用，或没条件检查（主机离线、目标是 IP 不用解析等） |
| 等待 | 在等主机回报 |
| 需要升级 Agent | 这台主机的 Agent 低于 2.2.226，主机上的检查没做；在主机页点「升级 Agent」后重新诊断。其余项照常检查 |

**最可能的原因** 按 配置 → 主机 → 入口 → 链路 → 目标 的顺序，取第一项失败（没有失败就取第一项警告）。越靠前越根本：规则被停用了，端口当然不在听、目标当然连不上，先处理前面的。

## 检查项

### 配置（面板判断）

| 检查 | 怎么判 | 不通过时怎么办 |
|------|--------|----------------|
| 规则 / 隧道 / 转发链已启用 | 开关、是否在删除中、是否被隧道或转发组连带停用、是否被系统停用（例如端口冲突） | 按提示恢复上级资源或手动打开 |
| 目标地址 | 目标地址不为空，目标端口在 1-65535 | 编辑规则补上 |
| 入口端口在允许范围内 | 主机端口范围 / 白名单、隧道端口范围、套餐端口段 | 换范围内的端口，或请管理员放宽 |
| 转发方式可用 | 管理员没在「转发协议」里关掉这种方式；账户允许使用它 | 换一种转发方式，或请管理员授权 |
| 账户状态 | 账户启用、没到期、转发没被暂停（3 天内到期给警告） | 续期 / 充值 / 请管理员启用 |
| 流量额度 | 已用 ≥ 额度为失败，≥ 90% 为警告 | 重置流量或调高额度 |
| 规则数量配额 | 规则数超过套餐上限给警告 | 删掉不用的规则或升级套餐 |

管理员账户不受套餐、流量限制，这几项直接通过。

### 主机（面板判断）

链路上每台主机一项（入口、中转、出口）：

- **离线** → 失败。到那台主机上看 `systemctl status forwardx-agent`，以及面板地址、网络是否变了。
- **NEX 隧道上 FXP 握不上当前协议**（没装或太旧）→ 失败，升级 Agent 会一并装新 FXP。
- **Agent 低于 2.2.226** → 警告，主机上的那几项检查会显示「需要升级 Agent」。

### 入口

| 检查 | 谁来测 | 怎么判 |
|------|--------|--------|
| 规则在入口主机上运行 | 面板 | Agent 上报的运行状态；没跑为失败，还没报过为警告 |
| 端口没被别的规则占用 | 面板 | 和保存规则时同一套端口占用检查（规则、隧道、入站、换隧道后的临时桥接） |
| 入口域名 / 主机 DDNS | 面板 | 从面板解析域名，看是不是入口主机现在的 IP；解析失败为失败，解析到别的地址为警告（换 IP 后还没同步，或套了 CDN） |
| 端口在监听 | 主机 | 读 `/proc/net/tcp(6)`、`/proc/net/udp(6)`，看端口和协议（tcp / udp / 都要）有没有在听 |
| 内核转发规则 | 主机 | iptables / nftables 类型的规则不在本机监听，改为在 `nft list ruleset` / `iptables-save -t nat` 里找这个端口 |
| 防火墙放行端口 | 主机 | 看 ufw、firewalld、iptables（INPUT，内核转发看 FORWARD）、nftables 有没有挡住这个端口；明确拒绝为失败，默认丢包且没看到放行为警告。面板的「地区规则 / IP 封禁」生效时会在细节里注明。**云厂商安全组看不到，需要自己确认** |
| 本机连得上端口 | 主机 | 从主机连 `127.0.0.1:端口`（监听在具体地址时连那个地址），再连自己的公网 IP；本机都连不上为失败，只有公网 IP 不通为警告（NAT 机器常见） |
| 转发进程在运行 | 主机 | realm / socat 看对应的 systemd 服务，gost 看 `forwardx-runtime`，nginx 看 `forwardx-nginx`，NEX 隧道看 FXP 进程 |

### 链路（隧道、转发链）

- **隧道在中转 / 出口上运行**：面板记录的每台主机的隧道运行状态。
- **隧道端口在监听、防火墙放行**：在每台中转和出口主机上检查隧道监听端口。
- **每一段下一跳**：从每台主机 TCP 连下一跳的地址和端口（地址选法和延迟探测一致：连接地址 → 内网地址 → 入口地址）。连不上为失败，3 次里有失败为警告。NEX v2（WireGuard，UDP）不做 TCP 测试，看「延迟测试」。
- **转发链**：每台成员主机上的子规则的运行状态、监听，以及链上每一段的连通。

### 目标

| 检查 | 谁来测 | 怎么判 |
|------|--------|--------|
| 目标地址 | 面板 | IP 是公网地址为通过；内网 / 保留 / 回环地址为警告（除非它正好是面板里某台主机的地址）；域名从面板解析不了为警告——面板和主机的 DNS 可能不同，以主机上的解析结果为准 |
| DNS 解析 | 主机 | 在拨号的那台主机上用系统解析器分别查 IPv4、IPv6，都查不到为失败；细节里带 `/etc/resolv.conf` 的 nameserver |
| 连得上目标 | 主机 | 在拨目标的那台主机上（直连规则是入口，隧道规则是出口，转发链是最后一跳）TCP 连 3 次，给出最快的延迟。UDP 规则只能尽力而为：收到「端口不可达」为失败，没回包为跳过（很多 UDP 服务不回空包） |

主机上的整组检查最多 30 秒，超时的项显示为警告。

## 常见结论怎么处理

- **端口没有程序在听**：先看同一组里的「运行状态」和「转发进程」。端口可能被别的程序占了（`ss -ltnup | grep :端口`），或者转发程序起不来（`journalctl -u forwardx-agent -n 100`）。
- **本机通、外面不通**：多半是防火墙或云安全组。先看「防火墙放行端口」那一项，再去云控制台放行端口。
- **连不上下一跳 / 目标，连接超时**：对端防火墙丢包或路由不通；**拒绝连接**：对端端口没开。
- **入口域名解析到别的 IP**：主机换过 IP 而记录还没更新，等 DDNS 同步或 TTL 过期；套了 CDN 时这是正常的。

还是查不出来时，点 **复制结果**，连同 [常见问题排查](./troubleshooting.md#收集诊断信息) 里的诊断信息一起发工单。

## 网络测试页：Ping 摘要、逐跳路由、配置体检 {#network-test}

> 不需要新版 Agent：摘要读的是 Agent 一直在跑的 ping / traceroute / mtr 的输出，配置体检只读面板里已有的状态

侧栏 **网络测试** 页（`/looking-glass`）从选中的 Agent 主机发起 Ping、Traceroute、MTR、TCPing。测完以后：

- **Ping 摘要**：结果卡顶部一行 **发送 / 收到 / 丢包率 / 最小 / 平均 / 最大 / 抖动**。抖动是相邻两次回包往返时间之差的平均；iputils 的 ping 还会另外写出标准差（mdev）。下面一两句结论，例如「一个回包都没收到：目标可能不回 ICMP……用 TCPing 测目标端口确认」。Agent 只发 4 个包，丢一个就是 25%，偶发丢包不必紧张，持续丢包再用 MTR 看。命令中途超时、没有统计行时，按已收到的回包算，并注明数字不完整。
- **逐跳展示**：Traceroute / MTR 的结果默认是一张逐跳表（跳数、地址、无回应或丢包、平均 / 最好 / 最差延迟，MTR 还有发送数和标准差），右上角可切回 **原始输出**。表上面几句结论：
  - 到没到目标（最后一跳是不是目标地址）；最后几跳全是 `*` 时提示「不一定是不通，用 TCPing 确认」；
  - MTR 终点丢包时，指出 **从第几跳开始一直丢到终点**——问题多半在那一跳附近；
  - 中间跳丢包、终点不丢：说明是路由器对探测限速，**不影响业务**，不报警；
  - 某一跳比上一个有回应的跳多出 50 ms 以上时点出来（跨境、跨运营商出口常见）；`!H` `!N` 这类不可达注记也会单独说。
  - Traceroute 每跳只有 3 个探测，「无回应」比例只能看个大概；看丢包用 MTR（每跳 10 个）。
- 「最近测试」卡片上也带一行摘要（Ping 的丢包和平均延迟、路由的跳数）。

认不出的输出（例如主机上没装 mtr 时 Agent 返回的安装提示）不出摘要，只显示原始输出。

### 配置体检 {#config-check}

页面下方的 **配置体检** 对着当前选中的测试主机，或这台主机上的一条规则（管理员能选全部规则，普通用户只能选自己的），把面板里已有的状态过一遍，给出和一键诊断同样的 **通过 / 警告 / 失败 / 跳过** 清单，每项一句结论、一句处理建议，最上面是最可能的原因，**复制结果** 可贴到工单里。

体检 **只读**：不发探测、不给主机派任务、不改任何配置，随时可以点。

**整台主机** 检查：

| 检查项 | 看什么 |
|--------|--------|
| Agent 安装 | 主机绑没绑 Agent；没绑时只出这一项，告诉你去执行安装命令 |
| 主机在线 | 和一键诊断的主机项一样：在线 / 离线（最后心跳时间）、Agent 版本 |
| Agent 版本 / FXP 运行时 | 该升级的是哪一件：Agent 落后于面板带的版本是警告；Agent 已是最新但 FXP 没装或握不上当前隧道协议也是警告（用不到 NEX 隧道可以不管）；FXP 只是有新版算通过 |
| IPv6 监听 | 内核关了 IPv6（Agent 2.2.256 起上报）时提示转发只听 IPv4 |
| 资源占用 | 最近 3 分钟内的 CPU / 内存 / 磁盘使用率，任一项 ≥ 90% 警告；没有近期采样时跳过，不拿旧数据下结论 |
| 节点维护 / 流量故障转移 | 主机在维护中、或流量到了故障转移阈值被暂停组调度 |
| 规则运行 | 这台主机上启用的规则谁没在运行、为什么——原因和规则卡上那枚标签同一套（端口被谁占着、运行时没装、IPv6 不可用、内核转发没装全……），每种原因给对应的处理办法；主机离线时不下结论 |
| 端口冲突 | 规则之间入口端口（含端口段）和协议重叠；没在运行的规则在面板端口表里查到端口还被别的规则 / 隧道 / 入站用着；入口端口上有不归 NEX 管的程序在监听（Agent 2.2.255 起的端口占用核对，更老的 Agent 会注明查不了） |

资源占用、维护和流量暂停只给管理员和主机的主人看；被授权使用这台主机的普通用户只看到 Agent、版本、IPv6 监听和自己的规则。

**某一条规则** 检查：就是这条规则一键诊断里 **面板这一半** 的项（开关、目标、入口端口范围、转发方式、账户和流量额度、经过的每台主机、运行状态、端口冲突、入口域名、目标地址），另外补上：

- 没在运行时，接上 Agent 报的原因和对应建议；
- 入口端口上有外来程序在监听时，单列一项警告；
- 经过的主机里 Agent 版本过旧的，各列一项警告。

要到主机上实测的项（端口有没有在听、防火墙、目标拨不拨得通）体检不做，结果下面会写「还有 N 项要到主机上实测」——到规则列表点这条规则的 **诊断 → 一键诊断**。

接口：`lookingGlass.configCheck`（参数 `hostId` 或 `ruleId` 二选一）、`lookingGlass.configCheckRules`（某台主机上能选的规则）。普通用户受系统设置里「普通用户可见网络测试」开关约束，和网络测试本身一样。

## 用接口调（API 令牌、MCP）

诊断有一组按「对象类型 + id」的统一接口（2.3.506）：`kind` 是 `rule`、`line`（开了线路组的规则）、`tunnel`、`forwardGroup`。

| 接口 | 做什么 |
|------|--------|
| `diagnostics.start` / `diagnostics.status` | 一键诊断清单：start 拿到 sessionId，每 2 秒用 status 问一次 |
| `diagnostics.latencyStart` / `diagnostics.latencyStatus` | 延迟测试：开一轮 / 看上一次（或正在跑的）结果，三种对象返回同一个样子 |
| `diagnostics.speedStart` / `diagnostics.speedStatus` | 测带宽：`line` 测线路此刻在走的那条（或 `pathKey` 指定的），`tunnel` 按隧道经过的机器拆段 |
| `diagnostics.faultBundle` | 故障包（只读） |

原来各自的接口（`rules.startSelfTest`、`tunnels.test`、`forwardGroups.test`、`lineDiagnostics.segmentSpeedStart`、`lookingGlass.pairSpeedStart` …）都还在，统一接口只是转调它们。
