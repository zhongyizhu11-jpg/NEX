# 转发组、入口组与出口组

NEX 提供三类”组”资源，分别服务于不同场景：转发组用于业务入口的高可用故障转移，入口组和出口组用于复用主机集合、简化多规则配置。

---

## 转发组

### 概念

转发组让多台入口主机同时为同一个目标提供服务。任意时刻只有一台主机作为当前入口，其余成员作为备用。结合 DDNS，故障时系统自动将域名切换到下一台可用主机，实现业务连续性。

```
入口 A ──┐
入口 B ──┼──> 目标（业务端口 / 协议 / 目标地址）
入口 C ──┘
```

> 业务端口、协议和目标地址仍在转发规则中单独配置，转发组只管理入口主机集合及故障切换策略。

### 成员管理

- 成员列表中的顺序即优先级，排在最前的主机为首选入口。
- 拖动成员可调整优先级；保存后会立即刷新所有引用该组的资源。
- 主机型转发组使用主机成员，隧道型转发组使用隧道成员；多入口隧道场景请使用入口组。

### 故障转移与 DDNS

当前入口失效并持续达到组内配置的**故障窗口**时，系统切换到下一个可用成员，并同步更新 DDNS 解析记录。

| 设置 | 行为 |
|------|------|
| 开启「恢复后切回」 | 高优先级成员恢复后自动切回 |
| 关闭「恢复后切回」 | 保持当前成员，直到它再次失效才继续切换 |

> 故障窗口时长在转发组配置页调整，默认值兼顾响应速度与抖动抑制。

### 按运营商线路解析

DDNS 服务商是腾讯云 DNSPod、阿里云 DNS 或华为云 DNS 时，成员列表的「线路」一列可以把成员分到运营商线路上（电信、联通、移动、境外……）。每条线路按同样的规则单独挑成员：电信线路只在分到电信的成员里按顺序挑，没分线路的成员留在默认线路。某条线路的成员全不可用时，默认改用默认线路的健康成员（也可以设成删掉这条线路的记录）。详见 [DDNS · 分线路解析](./ddns.md#group-ddns-lines)。

## 入口组

入口组将多台入口主机保存为一个可复用资源，供隧道、转发链或端口转发直接引用，避免在每条规则中重复填写相同的主机列表。端口转发挂上入口组后，组里每台主机都同时监听规则的入口端口、转到同一目标，组内加减主机自动同步。

- 可为入口组配置统一的 DDNS 域名，由系统自动维护解析记录。
- 可以按运营商线路分配成员（例如电信 → 一台、联通 → 另一台），每条线路发布这条线路全部健康的成员，按带宽排序和流量剔除都在线路内生效，见 [DDNS · 分线路解析](./ddns.md#group-ddns-lines)。支持腾讯云 DNSPod、阿里云 DNS、华为云 DNS。
- 也可关闭自动解析，改由自行维护 DNS 记录。
- 引用入口组后，系统按成员数量生成对应入口路径；成员或地址变更后，所有引用资源会同步刷新。

### 按带宽排序解析

（2.3.454 之前叫「多入口带宽加权分流」。）

默认情况下入口组会把所有健康成员一起发布到入口域名，客户端落到哪一台由解析器决定。开启「按带宽排序解析」后，入口域名照旧解析出**全部**健康入口，面板按带宽（或权重、剩余带宽）给这些入口排一个先后，并在编辑弹窗里显示带宽合计、实时已用和每台的占用率。

> **它现在不改变客户端被分到哪一台。** 一个域名下的多条记录在 DNS 里是一个没有顺序的集合：服务商和各级解析器返回时会自己轮换、打乱，面板排的先后带不过去；而且成员没变时面板不会为了换顺序去重写记录。所以开不开这个选项，各台入口接到的客户端大体还是平均的 —— 以前这里写的「大带宽的入口通常会接到更多客户端」不成立。按服务商的记录权重真正分流量在后续版本做。
>
> 现在要分流量：
> - 要**按比例**分连接：用订阅里的「负载均衡」组（Clash / Mihomo 客户端按线路带宽加权，见[线路组 · 常见问题](./failover.md)）。
> - 要把**一条连接拆开**同时走几台：用隧道中转的[单连接叠加](./tunnels.md#单连接叠加)。

- 在成员列表中为每台入口填写**上行 Mbps**；留空或填 0 时用主机上的「线路带宽」，再没有就按其余成员的中位带宽估算。
- **权重**用于手动指定排序比重，填 0 表示按所选依据自动计算。
- 编辑弹窗里能看到入口带宽合计、实时已用带宽和每台入口的占用率。

排序依据：

| 依据 | 怎么排 |
|------|----------|
| 按权重 | 权重高的排前面 |
| 不分先后 | 不看带宽，适合同规格机器 |
| 按带宽 | 线路带宽大的排前面 |
| 按剩余带宽 | 在带宽的基础上扣掉实时已用，现在闲的排前面 |

排序只影响面板里的先后和占用率显示，不改变健康判定，不会让任何一台健康入口从入口域名中消失，也不会改变解析器把哪条记录给客户端。健康入口少于**最少健康前置**时不排序，并在组状态中说明原因。

> 按剩余带宽依赖主机指标上报。主机指标缺失或超过 5 分钟未更新时，该台入口按未占用处理。

## 入口健康度检测

转发组和入口组会从每台成员自己的 Agent 发出探测，判断该成员是否还能承载流量。检测方式有两种：

| 方式 | 行为 | 适用场景 |
|------|------|----------|
| TCPing | 连接目标的 IP 和端口 | 需要确认端口真的可用 |
| Ping | 只发 ICMP 测延迟，不需要端口 | 目标不开放 TCP 端口，或只关心链路通断和延迟 |

- TCPing 的目标要写成 `主机:端口`，留空默认 `www.189.cn:80`；IPv6 用 `[地址]:端口`。
- Ping 的目标只填主机，留空默认 `www.189.cn`；IPv6 直接填地址。填了端口也会被忽略，不会报错。
- 切换检测方式会清空成员已记录的健康状态，避免沿用上一种方式得出的判定。

> Ping 依赖目标响应 ICMP。部分云厂商默认屏蔽 ICMP，这种目标即使正常也会被判为不健康，选之前先在成员主机上手动 ping 一下确认。

## 出口组

出口组将多个出口主机保存为一个隧道出口资源，支持以下能力：

- **出口复用**：多条隧道共用同一组出口，统一管理。
- **分配方式**（2.3.534 起统一成一个下拉框，链路负载均衡、出口组、线路组都是这一套）：
  - 常用：**自动**（推荐：看延迟、抖动、负载和带宽，新连接给最好的那台）/ **主备**（按顺序用第一台，坏了或一直抖才换下一台）/ **按访客固定**
  - 自定义：**延迟优先** / 按负载 / **按权重**（每台出口旁边可以手填份数，例如 5 : 3 : 2；全部填了才按填的分，有空的按线路带宽算）/ 轮流 / 随机
  - 新建出口组不预选，要自己挑一种。老的「只用第一个」显示成「主备」（坏了自动换下一台）。
- **检测与切换**（默认收起）：多久探一次（默认 2 秒）、几次不通算坏（2 次）、恢复要连续通几次（3 次）、比最快的慢多少就少分（50ms）、抖动超过多少算抖（30ms）、持续多久才处理（30 秒）、抖动大的时候「少分 / 切走 / 不管」、刚恢复的慢慢加量。最下面一句「实际效果」跟着设置变。内置防来回乱切：切过去至少用 1 分钟，主备里原来那台稳定 5 分钟才切回，一小时切 3 次以上就放慢（NEX 隧道由入口的 FXP 执行；GOST 隧道的「延迟优先」由面板排出口顺序时执行「至少用 1 分钟」和「切得太勤放慢到 5 分钟」）。
- **看的是「出口连得上目标吗」**（2.3.534 起）：以前负载均衡只看「入口连得上出口吗」，出口到落地丢包、连不上它看不见，照样往那台分。现在每台出口按「多久探一次」探规则的目标：
  - NEX 隧道（入口和出口的 FXP 都 ≥ 2.2.142）：出口连完目标先回报结果，连不上入口**当场换下一台出口**，把已经发出去的内容重放过去，用户感觉不到；按「出口 + 目标」记延迟、抖动、丢包，自动 / 延迟优先按整条延迟挑，抖的按设置少分或切走。
  - GOST 隧道：做不到一条连接里换出口，连不上目标的出口约 5～10 秒内从这条规则里**自动摘掉**（热更新，正在传的连接不断），恢复后加回。
  - 三台都连不上时不摘、不乱切，规则上直接写「多半是目标本身的问题，换出口没用」。
  - 规则卡上写清楚是哪台出口的问题（例如「3 台出口里 jinx 到目标丢包 8%，已少分」）；主出口连不上、别的出口能通时规则标橙不标红。链路卡上点「负载均衡 ×N」能看到每台出口到目标的延迟和抖动。
- **按负载**（推荐）：NEX 隧道的入口记着每台出口机现在的流量（10 秒均值）、挂着的连接、刚开的连接和握手延迟，新连接给「流量 ÷ 线路带宽」最低的那台；握手慢 50ms 以上的往后放；出口多于 3 台时随机挑两台比一比，免得几台入口同时挤向同一台。连接很长（代理、视频）时比按权重均匀得多，能把几台出口一起跑满。GOST 隧道看不到实时流量，按线路带宽加权随机；nginx 隧道用 least_conn + 权重。需要 Agent 2.2.232，更早的当轮流。
- **按访客固定**：同一个来源 IP 总走同一台。用的是一致性哈希：一台出口挂了，只有原来落在它上面的访客换出口，其余人不动；一台出口分到的访客比它该分的多 25% 以上时，新来的访客往下一台放。
- **刚恢复的出口**：从挂掉恢复后的 1 分钟里，按负载、按权重都只给它一小份，再慢慢加到满份，免得新连接一下子全涌过去。
- **按权重**：按每台出口主机的「线路带宽」分新连接，500M 和 300M 两台就是 5:3，交错着分，不会连着几条都压在一台上。份数在表单里直接写出来。有一台没填线路带宽（也没有限速、主机名里也没写带宽）时按平均分。GOST 隧道按份数加权随机，nginx 写 weight；这两种不挑 Agent 版本。NEX 隧道要求 Agent 不低于 2.2.232，更早的当轮流处理。
- 「按权重」默认按主机的「线路带宽」分，带宽大的出口多分连接。

规则列表中显示出口组名称，并可展开查看实际使用的出口节点，不再以第一台主机名称替代出口组名称。

## 入口组 vs 出口组

| 维度 | 入口组 | 出口组 |
|------|--------|--------|
| 用途 | 统一管理多个入口主机 | 统一管理多个出口主机 |
| 引用方 | 隧道入口 / 转发链 | 隧道出口 |
| DDNS 支持 | 支持（可选） | 不适用 |
| 负载均衡 | 只能按带宽排序解析（不是准确比例） | 支持（按连接分） |

## 状态说明

组成员及组整体都有独立状态：

| 状态 | 含义 |
|------|------|
| 在线 | 成员 Agent 与面板保持连接 |
| 已启用 | 组配置开关已打开 |
| 可用 | 由成员在线状态与最近探测结果共同决定 |

> “在线”不等于”可用”——Agent 在线但端口不通时，仍会被探测标记为不可用。

拖动成员可调整优先级，保存后会刷新引用关系。

## 命名建议

组名应能直接区分用途，便于在规则列表中快速识别：

- 入口组：`香港入口`、`新加坡入口-BGP`
- 出口组：`日本出口`、`美国出口-住宅IP`
- 转发组：`游戏入口故障转移`、`主站高可用入口`
