# 转发组、入口组与出口组

NEX 提供三类”组”资源，分别服务于不同场景：转发组用于业务入口的高可用故障转移，入口组和出口组用于复用主机集合、简化多规则配置。

---

## 转发组

### 概念

转发组让多台入口主机同时为同一个目标提供服务。任意时刻只有一台主机作为当前入口，其余成员作为备用。结合 DDNS，故障时系统自动将域名切换到下一台可用主机，实现业务连续性。

```
入口 A ──┐
入口 B ──┼──> 目标（业务端口 / 协议 / 目标地址）
入口 C ──┘
```

> 业务端口、协议和目标地址仍在转发规则中单独配置，转发组只管理入口主机集合及故障切换策略。

### 成员管理

- 成员列表中的顺序即优先级，排在最前的主机为首选入口。
- 拖动成员可调整优先级；保存后会立即刷新所有引用该组的资源。
- 主机型转发组使用主机成员，隧道型转发组使用隧道成员；多入口隧道场景请使用入口组。

### 故障转移与 DDNS

当前入口失效并持续达到组内配置的**故障窗口**时，系统切换到下一个可用成员，并同步更新 DDNS 解析记录。

| 设置 | 行为 |
|------|------|
| 开启「恢复后切回」 | 高优先级成员恢复后自动切回 |
| 关闭「恢复后切回」 | 保持当前成员，直到它再次失效才继续切换 |

> 故障窗口时长在转发组配置页调整，默认值兼顾响应速度与抖动抑制。

面板刚启动、或者数据库故障刚恢复时，有一小段时间（最长 90 秒）不会自动切换：这时面板还不知道哪些成员真的在线，要等每台成员主机重新上报、或者确认它沉默满了离线时间，才开始按健康状态切。期间组状态写着「面板刚启动或数据库刚恢复：还有 N 台成员主机没重新上报」。人工操作（保存组、调顺序、立即同步）不受这个限制。

### 按运营商线路解析

DDNS 服务商是腾讯云 DNSPod、阿里云 DNS 或华为云 DNS 时，成员列表的「线路」一列可以把成员分到运营商线路上（电信、联通、移动、境外……）。每条线路按同样的规则单独挑成员：电信线路只在分到电信的成员里按顺序挑，没分线路的成员留在默认线路。某条线路的成员全不可用时，默认改用默认线路的健康成员（也可以设成删掉这条线路的记录）。详见 [DDNS · 分线路解析](./ddns.md#group-ddns-lines)。

## 入口组

入口组将多台入口主机保存为一个可复用资源，供隧道、转发链或端口转发直接引用，避免在每条规则中重复填写相同的主机列表。端口转发挂上入口组后，组里每台主机都同时监听规则的入口端口、转到同一目标，组内加减主机自动同步。

- 可为入口组配置统一的 DDNS 域名，由系统自动维护解析记录。
- 可以按运营商线路分配成员（例如电信 → 一台、联通 → 另一台），每条线路发布这条线路全部健康的成员，按带宽排序和流量剔除都在线路内生效，见 [DDNS · 分线路解析](./ddns.md#group-ddns-lines)。支持腾讯云 DNSPod、阿里云 DNS、华为云 DNS。
- 也可关闭自动解析，改由自行维护 DNS 记录。
- 引用入口组后，系统按成员数量生成对应入口路径；成员或地址变更后，所有引用资源会同步刷新。

### 成员的拿掉与加回

- **拿掉**：成员异常持续满「异常多久切」就从入口域名里拿掉。
- **加回来**：成员恢复后要**连续正常满「恢复多久切回」**才加回解析（从面板第一次看到它恢复算起；机器刚从离线回来的，从它回来那一刻算起）。新加进组的成员不用等。
- **频繁进出**：同一个成员一小时内被自动拿掉、加回三次以上，下一次加回要多等（5 分钟起，每多一次翻倍，最多 1 小时），组状态里会写「频繁进出，暂缓加回」。
- **全部不健康**：保留上一轮发布的**整组**记录，不改服务商那边的解析（以前会缩成一条）。全部入口同时判坏，多半是检测这一侧的问题；缩成一条等于把所有访客压到一台上。这时只要有一台恢复健康，马上加回，不等上面两条。
- **全部因流量到阈值被暂停**：记录会被清空（不能继续往快被停机的机器上导流），并在组的事件里记一条。

### 按带宽排序解析

（2.3.454 之前叫「多入口带宽加权分流」。）

默认情况下入口组会把所有健康成员一起发布到入口域名，客户端落到哪一台由解析器决定。开启「按带宽排序解析」后，入口域名照旧解析出**全部**健康入口，面板按带宽（或权重、剩余带宽）给这些入口排一个先后，并在编辑弹窗里显示带宽合计、实时已用和每台的占用率。

> **只开这一项不改变客户端被分到哪一台。** 一个域名下的多条记录在 DNS 里是一个没有顺序的集合：服务商和各级解析器返回时会自己轮换、打乱，面板排的先后带不过去；而且成员没变时面板不会为了换顺序去重写记录。所以只排序的话，各台入口接到的客户端大体还是平均的。要让解析真的按比例返回，再打开下面的[按权重解析](#按权重解析)（要 DNS 服务商支持）。
>
> 别的分流量的办法：
> - 要**按比例**分连接：用订阅里的「负载均衡」组（Clash / Mihomo 客户端按线路带宽加权，见[线路组 · 常见问题](./failover.md)）。
> - 要把**一条连接拆开**同时走几台：用隧道中转的[单连接叠加](./tunnels.md#单连接叠加)。

- 在成员列表中为每台入口填写**上行 Mbps**；留空或填 0 时用主机上的「线路带宽」，再没有就按其余成员的中位带宽估算。
- **权重**用于手动指定排序比重，填 0 表示按所选依据自动计算。
- 编辑弹窗里能看到入口带宽合计、实时已用带宽和每台入口的占用率。

排序依据：

| 依据 | 怎么排 |
|------|----------|
| 按权重 | 权重高的排前面 |
| 不分先后 | 不看带宽，适合同规格机器 |
| 按带宽 | 线路带宽大的排前面 |
| 按剩余带宽 | 在带宽的基础上扣掉实时已用，现在闲的排前面 |

排序只影响面板里的先后和占用率显示，不改变健康判定，不会让任何一台健康入口从入口域名中消失，也不会改变解析器把哪条记录给客户端。健康入口少于**最少健康前置**时不排序，并在组状态中说明原因。

> 按剩余带宽依赖主机指标上报。主机指标缺失或超过 5 分钟未更新时，该台入口按未占用处理。

### 按权重解析

打开「按带宽排序解析」之后，下面多一个**按权重解析**：把上面算出来的份额写成 DNS 服务商的**记录权重**，服务商解析时按比例返回各个入口。份额最大的入口权重是 100，其余按比例（最小 1）。

| DNS 服务商 | 支持 | 怎么实现 |
|------|------|------|
| 腾讯云 DNSPod | 支持 | 每条记录带权重（0～100） |
| 阿里云 DNS | 支持 | 打开这个子域名的「权重配置」，逐条记录设权重（1～100） |
| 华为云 DNS | 支持 | 一个入口一个记录集，各带各的权重（没开时是一个记录集装全部入口） |
| Cloudflare | 不支持 | 普通 DNS 记录没有权重，按比例分流是它单独收费的 Load Balancing |
| 自定义 Webhook | 不支持 | 面板只把入口地址交给你的接口，记录权重不归面板管 |

不支持时这个选项是灰的，下面写着原因。几点要知道的：

- 只对 **A / AAAA** 记录、**默认线路**生效；CNAME 一个名字只能有一条，谈不上按比例；分到运营商线路上的记录不带权重。开了「同时发另一族」时，另一族的记录跟着同一批成员带同样的权重。
- 至少要有两个健康入口、并且带宽聚合在生效（健康入口不少于「最少健康前置」）才带权重；不满足时按普通方式发布。
- **按剩余带宽**的份额跟着实时流量变。为了不让流量一抖就改一次解析，权重变化不到 15（满分 100）时不重写记录。
- 权重是「解析返回哪条记录」的比例，不是连接数的比例：运营商的递归解析器会缓存结果（TTL 内同一个解析器下的用户拿到的是同一条），用户少、或者集中在少数几个解析器后面时，实际比例会偏。部分服务商的免费套餐对同名记录条数、权重功能有限制，被拒绝时错误会显示在组状态里。
- 关掉这个选项（或者关掉带宽排序）时，面板会把服务商那边的权重设置收回去。

## 外部观察

成员的健康以前只听它**自己的 Agent** 说：Agent 还在心跳就算好。这有两个盲区——转发进程挂了、端口被防火墙拦了，Agent 照样心跳，这台入口其实已经没人连得上，却还留在解析里；反过来，一台入口只是到面板的那条路断了，访客用着好好的，却被当成离线拿掉。

**外部观察**让组里别的成员替面板去看：每个成员由最多 3 台别的机器（观察点）去连它**对外的入口地址和访客实际连的端口**。

- 探什么端口：主备转发组是这个成员的规则监听端口；入口组是用到这个入口组的隧道规则、端口转发、转发链在这台入口上的监听端口。每个成员最多探 3 个端口，TCP 优先；只有 UDP 的规则探 UDP 端口（说不准时退回 Ping）。任何一个端口连得上，就算这个观察点「连得上」它。共享 TLS 入站（SNI 分流）的规则不探。
- 谁当观察点：先用同组里别的启用成员，不够再用组编辑框里「额外的观察主机」指定的机器（成员只有一两台、或者想从别的网络看时用）。观察点要 **Agent 2.2.264 以上**；Agent 太旧的机器不当观察点，组卡片上会提示「需要升级 Agent」。

怎么判：

| 情况 | 结果 |
|------|------|
| 成员自己报告正常，至少 2 个观察点（在线的观察点不足 2 个时是全部在线的；在线观察点暂时没结果不会降低这个门槛）**持续**「异常多久切」那么久连不上它 | 判不可用，从解析里拿掉 / 主备组切走 |
| 成员的 Agent 面板连不上，但有观察点连得上它 | 继续发布，状态写「面板连不上，访客可达」。主备组里它是当前入口就留着不切走，但不会主动切过去 |
| 成员的 Agent 面板连不上，也没有观察点连得上 | 和以前一样按离线处理 |
| 判了不可用之后观察点重新连上 | 解除，再连续正常满「恢复多久切回」才加回来 |
| 没有可用的观察点（单成员组、别的成员 Agent 太旧、观察点都离线） | 只看成员自己的报告，成员悬停提示里会写明 |

一个观察点「连不上」的结论，要同时满足下面几条才作数，免得观察点自己有问题时误伤成员：

- 观察点自己在线，结果是 2 分半以内的（观察点每分钟报一次，有变化立刻报）；
- 它**以前连通过**这个成员——只放行特定来源 IP 的防火墙后面，别的机器本来就连不上，这种不算；
- 它此刻连得上同组别的成员、或者连得上参照目标（开了入口健康度检测就是那个目标，否则是 `www.189.cn:80`）——观察点自己的网络坏了，谁都连不上，不算。

成员列表里每个成员的悬停提示把两样分开写：「自己报告：…；外部观察 2/3 可达」。组状态里也会写「N 个入口外部观察连不上」「N 个入口面板连不上但访客可达」。

> 外部观察对新建的组和**升级前就有的主备组、入口组都默认开着**（升级后不用改设置就生效；组卡片上会写「外部观察 N 个入口」）。
>
> 观察点是真的去连入口端口：每个观察点对它负责的每个成员、每个端口每 5～30 秒连一次（按组的故障 / 恢复时间定），连上就断；另外每个观察点还连一次参照目标（开了入口健康度检测就是那个目标，否则是 `www.189.cn:80`）。一个成员最多 3 个观察点 × 3 个端口。用 gost、realm 这类转发时，目标那边会看到一条马上关闭的连接；连接统计里也会多出这些。不想要可以在组编辑框里关掉「外部观察」（这个组就只看成员自己的报告，和以前一样）。
>
> 观察结果存在面板内存里，面板重启后要等观察点下一次上报（一分钟内）才重新有结果；「哪些观察点连通过它」「外部是否判了不可用」存在库里，重启后接着用。

## 入口健康度检测

转发组和入口组还可以从每台成员自己的 Agent 向一个目标发探测，判断该成员的出方向是否正常。检测方式有两种：

| 方式 | 行为 | 适用场景 |
|------|------|----------|
| TCPing | 连接目标的 IP 和端口 | 需要确认端口真的可用 |
| Ping | 只发 ICMP 测延迟，不需要端口 | 目标不开放 TCP 端口，或只关心链路通断和延迟 |

- TCPing 的目标要写成 `主机:端口`，留空默认 `www.189.cn:80`；IPv6 用 `[地址]:端口`。
- Ping 的目标只填主机，留空默认 `www.189.cn`；IPv6 直接填地址。填了端口也会被忽略，不会报错。
- 切换检测方式会清空成员已记录的健康状态，避免沿用上一种方式得出的判定。

> Ping 依赖目标响应 ICMP。部分云厂商默认屏蔽 ICMP，这种目标即使正常也会被判为不健康，选之前先在成员主机上手动 ping 一下确认。

## 出口组

出口组将多个出口主机保存为一个隧道出口资源，支持以下能力：

- **出口复用**：多条隧道共用同一组出口，统一管理。
- **分配方式**（链路负载均衡、出口组、线路组都是这一套，NEX 隧道和 GOST 隧道上是同一份算法）：最上面是**自动（推荐）**，其余在「其他方式」里单选。新建出口组默认就是「自动」+ 检测「均衡」，不改也能直接用；选了哪种，下拉框下面一句话写它会怎么做。老的「只用第一个」显示成「主备」。坏了的出口每种方式都会避开（见下面「看的是出口连得上目标吗」），下面只说怎么分：
  - **自动**：每台出口的延迟（入口到出口 + 出口到目标）、抖动、丢包、正在走的连接和线路带宽（NEX 隧道还看流量占了带宽几成）合成一个「代价」，新连接给代价低的那台。刚变慢、变忙的立刻少分，过一阵会再试它；出口多于 3 台时随机挑两台比一比，免得几台入口同时挤向同一台。
  - **主备**：先用第一台，连不上才换下一台（或者设成「抖动大的时候切走」而它一直抖），恢复稳定后切回。
  - **按访客固定**：同一个来源 IP 总走同一台。一台出口挂了，只有原来落在它上面的访客换出口，其余人不动，它回来以后这些访客又回到它上面。只要那台出口能用，同一个访客的连接再多也都走它（出口 IP 不变），不会因为它分得多就被挪走；访客多的时候按线路带宽加权分。不知道访客是谁时按轮流。
  - **延迟优先**：只在最快的那几台里分 —— 比最快的慢不到「延迟优先：差多少算一样快」（默认 50ms）的算一样快，组里按自动分；慢出这么多的不分。进了这一组的至少留 1 分钟，延迟卡在门槛上下时不会每条连接都换。
  - **按负载**：新连接给现在最闲的那台：看挂着的、刚开的连接数，按线路带宽折算；NEX 隧道还看流量占了带宽几成（利用率 = 流量 ÷ 线路带宽）。**有一台出口没填线路带宽，就都只按连接数分**。出口多于 3 台时随机挑两台比。连接很长（代理、视频）时比按权重均匀得多。
  - **按权重**：每台出口旁边可以手填份数（例如 5 : 3 : 2，全部填了才按填的分），没填按线路带宽算（500M 和 300M 就是 5 : 3），交错着分，不会连着几条都压在一台上。有一台不知道带宽时平均分。
  - **轮流** / **随机**：新连接一台一台轮着走 / 随机挑一台能用的；起点随机，几百条规则一起启动时不会都从第一台开始。
  - **刚恢复的出口**：从挂掉恢复后的 1 分钟里从一成慢慢加到满份（按访客固定、主备不加），免得新连接一下子全涌过去。
- **检测与切换**：检测灵敏度先选一档 —— **灵敏 / 均衡（默认）/ 稳定**，逐项的参数收在「高级」里：多久探一次（均衡 2 秒）、几次不通算坏（2 次）、恢复要连续通几次（3 次）、延迟优先：差多少算一样快（50ms，只对延迟优先起作用）、抖动超过多少算抖（30ms）、持续多久才处理（30 秒）、抖动大的时候「少分（降到 4 分之 1）/ 切走 / 不管」（抖动这三项只对 NEX 隧道起作用；GOST 隧道的抖动、丢包直接算进自动 / 延迟优先的代价）、刚恢复的慢慢加量。最下面一句「实际效果」跟着设置变。防来回乱切是内置的：GOST 隧道主备切过去至少用 1 分钟，一小时自动切 3 次以上，下一次要多等（5 分钟起翻倍，最多 1 小时）；NEX 隧道一台出口一小时里断到第 4 次起，下一次要从断开算起坏满 30 秒才放回（每多一次翻倍，最多 5 分钟）；到目标一小时断到第 4 次起，下一次要坏满 5 分钟才算恢复；主备里到目标刚恢复的出口稳够 5 分钟才切回去。
- **看的是「出口连得上目标吗」**（2.3.534 起）：以前负载均衡只看「入口连得上出口吗」，出口到落地丢包、连不上它看不见，照样往那台分。现在每台出口按「多久探一次」探规则的目标：
  - NEX 隧道（入口和出口的 FXP 都 ≥ 2.2.142）：出口连完目标先回报结果，连不上入口**当场换下一台出口**，把已经发出去的内容重放过去，用户感觉不到；按「出口 + 目标」记延迟、抖动、丢包，自动 / 延迟优先按整条延迟挑，抖的按设置少分或切走。
  - GOST 隧道（入口机 Agent ≥ 2.2.264）：几台出口由入口机 Agent 的本机代理挑，TCP 和 UDP 都是。入口自己直接探每台出口机（默认 2 秒一轮、2 次不通判坏：出口断电 / 被黑洞约 5 秒内摘掉，回来约 6 秒放回），不依赖面板；一条连接「连上出口、出口一个字节没回就被关」（出口连不上目标）时**当场换下一台出口重发**，同时经那台出口复核一次，确认走不通就摘掉；出口到目标的延迟和「连不上目标」由出口机探、经面板提示给入口。切换不改 GOST 配置，正在传的连接不断。带中转的 GOST 链路入口探不到出口机，靠「连接被关 → 换走 → 复核」和面板提示发现。入口机的 Agent 低于 2.2.264 时只走主出口，链路和规则上会写「需要升级 Agent」。
  - Nginx 隧道：**基础支持**。出口由入口机的 nginx 自己分，只看出口机连不连得上，不看出口到目标通不通；「自动」「延迟优先」是「连接数最少 + 线路带宽」；检测灵敏度、手动指定出口对它不起作用。
  - 三台都连不上时不摘、不乱切，规则上直接写「多半是目标本身的问题，换出口没用」。
  - 规则卡上写清楚是哪台出口的问题（例如「3 台出口里 jinx 到目标丢包 8%，已少分」）；主出口连不上、别的出口能通时规则标橙不标红。链路卡上点「负载均衡 ×N」能看到每台出口此刻的状态（在用 / 备用 / 连不上 / 不稳 / 慢启动中 / 已指定）、到目标的延迟、分到几成；不是在用的那台写原因（连不上的是出口机本身还是到目标）和该查什么，下面是最近几次切换（几点、从什么到什么、为什么）。

规则列表中显示出口组名称，并可展开查看实际使用的出口节点，不再以第一台主机名称替代出口组名称。

## 入口组 vs 出口组

| 维度 | 入口组 | 出口组 |
|------|--------|--------|
| 用途 | 统一管理多个入口主机 | 统一管理多个出口主机 |
| 引用方 | 隧道入口 / 转发链 | 隧道出口 |
| DDNS 支持 | 支持（可选） | 不适用 |
| 负载均衡 | 只能按带宽排序解析（不是准确比例） | 支持（按连接分） |

## 状态说明

组成员及组整体都有独立状态：

| 状态 | 含义 |
|------|------|
| 在线 | 成员 Agent 与面板保持连接 |
| 已启用 | 组配置开关已打开 |
| 可用 | 由成员在线状态与最近探测结果共同决定 |

> “在线”不等于”可用”——Agent 在线但端口不通时，仍会被探测标记为不可用。主备转发组和入口组的「端口通不通」是别的成员替面板去连出来的，见上面的[外部观察](#外部观察)。

节点池的机器数比组的成员上限（20）多时，跟着这个池的组放不下：保存节点池时会直接提示是哪个组、要减到多少台；之前已经存成这样的，节点池卡片上会写「成员没同步」。

拖动成员可调整优先级，保存后会刷新引用关系。

## 命名建议

组名应能直接区分用途，便于在规则列表中快速识别：

- 入口组：`香港入口`、`新加坡入口-BGP`
- 出口组：`日本出口`、`美国出口-住宅IP`
- 转发组：`游戏入口故障转移`、`主站高可用入口`
