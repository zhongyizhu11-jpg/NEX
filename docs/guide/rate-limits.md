# 限速、复制模式与 SOCKS5 落地

## 多级限速

一条转发同时受下面几级限速约束，**每个方向取最严的那一级**。每一级都是一个共享的桶：同一级下所有规则、所有连接共用，开多少线程都绕不过去。

| 级别 | 在哪里设 | 范围 | 上下行 |
| --- | --- | --- | --- |
| 用户 | 用户管理 → 编辑 → 流量 → 转发限速 | 这个用户在一台主机上的所有转发 | 分开设 |
| 用户突发 | 同上 → 突发峰值 / 突发时长 | 同上 | 跟着上下行 |
| 隧道 | 隧道编辑 → 限速 | 这个用户在这条隧道上的转发 | 同一个数 |
| 转发组 | 转发组编辑 → 限速 | 这个用户在这个转发组上的转发 | 同一个数 |
| 规则 | 转发规则表单 → 限额 → 限速（管理员设） | 这条规则（含转发组成员、路由中转）的所有连接 | 同一个数 |
| 整台主机 | 主机编辑 → 整台主机转发限速 | 这台机器上所有用户的转发加起来 | 同一个数 |

上行指客户端 → 目标，下行指目标 → 客户端。填 0 表示这一级不限。

规则限速由管理员设置：它只会和其他几级叠加、取最严，只会更慢，不会更快。

### 先突发、再降速

给用户设了上下行速度之后，可以再设「突发峰值」和「突发时长」：

- 一开始按峰值跑，大约能跑「突发时长」那么久；
- 用满了就降回上下行速度；
- 用得少的时候（低于上下行速度）额度慢慢回满，速度自动恢复。

例如上下行 100 Mbps、突发峰值 300 Mbps、突发时长 60 秒：下载大文件时先以 300 Mbps 跑约 30 秒（额度 = (300 − 100) × 60 秒），之后稳定在 100 Mbps；停用一阵后又能突发。峰值不高于上下行速度时突发不生效。

### 适用范围

| 转发方式 | 上下行分开 | 多级叠加 | 突发 |
| --- | :---: | :---: | :---: |
| iptables / nftables / realm / socat / nginx，Nginx 隧道入口 | ✓ | ✓ | ✓ |
| gost 转发 | ✓（每个方向取最严那级） | — | — |
| NEX（FXP）隧道入口 | ✓（每个方向取最严那级） | — | — |

完整的多级叠加和突发需要 Agent 2.2.230；旧 Agent 继续按「最严那一级」限速。

## 复制模式

中转「单连接叠加」的 NEX 隧道（至少两台中转）可以在隧道「···」菜单里开启**复制模式**：入口把每一片数据都从两条不同的中转各发一份，出口按序号去重、谁先到用谁。

- 一条中转断了，另一条上已经有同样的数据在路上，TCP 连接不会中断、也不用等超时重传。
- 代价是这条隧道的中转流量翻倍。
- 回程（出口 → 入口）同样复制，需要出口 FXP 2.2.133；出口是旧版本时只有去程复制。

不开复制模式时，单连接叠加照常把一条连接拆到多条中转上并行传输，一条中转出问题时由重传接管。

## SOCKS5 落地

「落地节点」新增 SOCKS5 协议（由 sing-box 提供）：

- 每份凭据是一组用户名 + 密码，由面板生成，可以开多份给不同的人；订阅里各家客户端（Clash / mihomo、sing-box、Surge、Loon、Quantumult X、Shadowrocket、v2rayN）都能导入。
- SOCKS5 **不加密**，只建议放在中转之后、或者自己信得过的线路上用。
- 派生出来的节点不开 UDP：SOCKS5 的 UDP 要连服务端另开的随机端口，经过中转的端口转发连不过去。

「客户端订阅 → 添加节点」也能直接粘贴 `socks://` 或 `socks5://` 链接。

Juicity、SSH 入站目前不支持：落地节点的运行时 sing-box 没有这两种入站。
