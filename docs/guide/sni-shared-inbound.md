# 共享 TLS 入站（SNI 分流）

一台主机上只有一个 443，却想给好几个网站、好几个用户都用上？共享 TLS 入站就是干这个的：管理员在主机上开一个 TCP 端口（通常是 443），多条规则（可以属于不同用户）共用它。Agent 读取 TLS 握手（ClientHello）里的 SNI（客户端要访问的域名），把连接原样交给对应的规则。

- **纯透传**：节点不终止 TLS、不需要证书，加密从客户端一直到你的目标服务都是端到端的。
- **适用于任何 TLS 服务**：HTTPS 网站、Trojan、VLESS-TLS 等基于 TCP 的 TLS 代理协议、走 TLS 的 API 等等（Hysteria2、TUIC 这类 QUIC/UDP 协议不适用）。只看 SNI，不看 HTTP Host，所以明文 HTTP 不能用这种方式分流。
- **可以接在隧道、转发链、转发组后面**：分到规则以后，可以由入口主机直接连目标，也可以再经隧道、转发链到出口，或者让转发组 / 端口转发资源的每台入口主机共用同一个 SNI 端口（见下面「规则怎么走」）。
- **计费和限速照旧**：每条规则的流量单独统计，套餐流量、按量计费、限速和普通规则一致。

::: warning 需要的 Agent 版本
- 入口主机直接连目标：Agent **2.2.224** 或更新。
- 经隧道、转发链、转发组 / 端口转发资源走：入口主机的 Agent **2.2.255** 或更新。

版本不够时，规则不会下发，规则卡片上显示「需要升级 Agent」；已有的直连规则不受影响。在主机列表里升级 Agent 即可。
:::

## 工作原理

```text
客户端 ──TLS(SNI=shop.example.com)──▶ 入口主机:443（共享 TLS 入站）
                                         │ 按 SNI 找到规则
                                         ▼
                      这条规则在入口主机上的入口（本机内部端口，不对外）
                                         │
                                         ▼
                      直连目标 / 经隧道到出口 / 经转发链逐跳 / 转发组成员直连
```

1. 客户端连接主机的入站端口，发出 ClientHello。
2. Agent 读出 SNI，在入站的路由表里**精确匹配**规则（`www.example.com` 和 `example.com` 是两个名字）。
3. 读到的握手字节原样交给规则在本机的入口，之后的数据双向透传。
4. 分不出去的连接直接关闭，不回任何 TLS 告警。

每条规则在入口主机上有一个面板自动分配的内部端口，规则自己的入口（直连规则的转发进程、隧道的入口、转发链的第一跳、转发组成员上的规则）只在本机回环地址上监听它，外部连不上。流量统计、限速、配额都挂在这个入口上，所以和普通规则完全一致。

## 规则怎么走

| 走法 | 在哪新建 | 路径 | 入口主机上要有什么 |
| --- | --- | --- | --- |
| 直连 | 转发规则 →「端口转发」页签 | 客户端 → 入口主机:443 → 目标 | 这台主机上的共享入站 |
| 经端口转发资源 | 转发规则 →「端口转发」页签，选「端口转发「资源名」· 主机 · 入站」 | 客户端 → 资源里任意一台入口:443 → 目标 | **每台**入口主机上都有同端口的共享入站 |
| 经隧道 | 转发规则 →「隧道转发」页签 | 客户端 → 隧道入口机:443 → 隧道 → 出口 → 目标 | 隧道入口机上的共享入站 |
| 经转发链 | 转发规则 →「转发链」页签 | 客户端 → 链的入口:443 → 中转 → … → 目标 | 链的入口主机（挂了入口组时是组里**每台**）上同端口的共享入站 |
| 经转发组（DDNS 主备） | 转发规则 →「转发组」页签 | 客户端 → 当前入口:443 → 目标 | **每台**成员主机上都有同端口的共享入站 |

### 多台入口主机怎么共用一个 SNI 端口

转发组、端口转发资源、挂了入口组的转发链都有好几台入口主机。新建规则时选的是其中一台主机上的入站（比如「香港 · 共享 443 :443」），其余每台入口主机**自动用它自己身上端口相同的那个入站**。所以管理员要在每台入口主机上各开一个同端口的共享入站，白名单也要都放行规则的域名。

一台主机的 443 永远只有一张路由表：这台主机上的直连规则、各个转发组在这台主机上的规则共用它，同一个域名在这张表里照样只能归一条规则。

某台入口主机用不了（没有同端口的入站、白名单不放行、名字已被这台主机上别的规则占了、Agent 太旧）时，规则在**这台**主机上不下发，其余主机不受影响；原因记在面板日志里。

### DDNS 只切到确认好的入口

Agent 2.2.255 起会把它装上的每张 SNI 路由表的版本号报给面板。面板看到入口主机报回来的版本号就是自己最近下发的那张、入站在监听、规则在这台主机上已经跑起来，才算这台入口的 SNI 配置**已确认**：

- **转发组**（DDNS 主备）：故障转移、恢复回切只会切到已确认的成员；没确认的成员在组的事件里记一条「共享 TLS 入站未就绪，暂不切到这个成员」，写明原因。
- **入口组**的入口域名：还没解析到的成员要等确认后才加进去。
- 当前正在用的入口不会因为「还没确认」被切走（比如面板刚重启、还没收到心跳时）。

主机详情的「共享 TLS 入站」里，入站在听但还没确认时显示「路由表待确认」，下面一行是监听以来分到规则 / 断开 / 规则入口拨不通的连接数，排查时有用。

## 管理员：在主机上开入站

在 **主机** 页打开主机详情，找到「共享 TLS 入站」一节，点「管理」→「新建共享 TLS 入站」。要给转发组、端口转发资源、转发链的入口组用时，在**每台入口主机**上各开一个同端口的入站。

| 设置 | 说明 |
| --- | --- |
| 名称 | 给人看的名字，用户选择入站时会看到。 |
| 端口（TCP） | 入站监听的端口，通常是 443。不能和这台主机上任何其他监听冲突（转发规则、隧道、落地节点、Agent 中转、其他入站）。每台主机最多 64 个入站。 |
| 允许的 SNI | 白名单，一行一个。`example.com` 放行它自己和所有子域名；`.example.com` 只放行子域名（不含 `example.com` 本身）。留空表示不限。 |
| 没有 SNI 的连接直接断开 | 默认开启。关闭后，没带 SNI 的连接交给默认规则（没有默认规则就断开）。 |
| 未知 SNI | 没有规则认领的域名：断开连接，或交给默认规则。 |
| 默认规则 | 只能是挂在这个入站上、属于管理员自己的规则。 |
| PROXY 头 | 「自动识别」时接受上游负载均衡发来的 PROXY Protocol v1/v2 头，用其中的真实客户端地址做限流。**只在前面确实有你信任的负载均衡时开启**，否则任何人都能伪造来源地址。 |
| 并发握手上限 | 同时在等 ClientHello 的连接数上限（1–4096，默认 128）；同一来源 IP 最多 16 个。 |
| 握手超时 | 等 ClientHello 的时间（1–30 秒，默认 5 秒），超时直接断开。 |

几条保护规则：

- 入站上还有规则（包括暂停的规则、转发组在这台主机上的规则）时不能删除，请先删除或迁走这些规则。
- 修改白名单时，如果新白名单不再覆盖已有规则的某个 SNI，保存会被拒绝。
- 停用入站后，挂在上面的规则都会停止，规则卡片显示「入站已停用」。

::: tip 面板不验证域名归属
任何能使用这台主机的用户，以及能使用以这台主机为入口的隧道、转发链、转发组的用户，都可以在规则里填域名。如果入站共享给多个用户，请用**白名单**把每个人限制在自己的域名范围内（比如给不同用户分配不同的入站，每个入站白名单只写对方的域名）。
:::

## 用户：把规则挂到入站上

1. 在 **转发规则** 页新建规则，选好页签：「端口转发」（直连或经端口转发资源）、「隧道转发」、「转发链」或「转发组」。隧道 / 转发链 / 转发组页签里先照常选好要用的隧道或转发资源。
2. 「入口方式」选 **共享 TLS 入站**（有可用的入站时才会出现）。
3. 选择入站，在「SNI 域名」里一行一个填写域名（1–32 个）。隧道页签只列隧道入口机上的入站；转发链 / 转发组页签列的是这个资源入口主机上的入站。
4. 填写目标地址和目标端口（目标就是你真正提供 TLS 服务的地方，证书也在那里）。
5. 保存。协议固定 TCP，没有源端口；规则卡片上显示「SNI：shop.example.com @ 主机:443」。

保存以后，入口方式和走法（直连 / 隧道 / 转发资源）都不能再改，需要换的话请新建规则。能改的是名字、目标、SNI 域名、开关，以及换到同一台主机（转发资源上：同端口）的另一个入站。

域名的规则：

- 会自动转成小写、去掉末尾的点，中文域名会转成 `xn--` 形式。
- 不能填 IP、通配符（`*.example.com`）、端口或 `https://` 之类的前缀。
- 同一个入站里，一个域名只能属于一条规则。**暂停的规则也会保留它的域名**，别人不能拿走；删除规则后域名才会释放。被占用时会提示「此 SNI 已被其他规则占用（暂停的规则也会保留 SNI）」。经转发资源的规则在每台入口主机的入站上都占着这些名字。
- 必须在入站的白名单范围内（经转发资源时：每台入口主机的入站白名单）。

::: warning 记得配置 DNS
每个 SNI 域名的 DNS 都要解析到入口：直连和经隧道时是入站所在的主机；经转发组时是组的入口域名（或入口主机）。客户端连接时用域名（或在客户端里把 SNI / 伪装域名设成这个域名），否则 SNI 对不上，连接会被直接断开。
:::

### 暂停的规则

规则暂停后，它的域名在入站上依然存在但不可用：用这些域名连进来的连接会被直接断开，**不会**落到默认规则上。这样可以避免一个用户停掉的规则，流量跑进别人的规则里。

### 计费、限速和配额

- 直连规则：和普通端口转发一样，统计和限速在规则自己的入口上。
- 经隧道：这条规则就是一条普通的隧道规则，只是入口换成了本机内部端口；隧道的限速、按隧道计费、出口策略都照旧。
- 经转发链 / 转发组 / 端口转发资源：和这些资源上的普通规则一样，由每台入口主机上的那份规则统计、限速，计费和这些资源的普通规则同一套。
- SNI 规则不占对外端口，端口额度不算它；规则条数额度照常算。

## 现在不支持的组合

| 组合 | 说明 |
| --- | --- |
| 挂了入口组的隧道 | 隧道入口组里别的主机身上没有这张 SNI 路由表。请改用单入口的隧道，或用转发链 / 端口转发资源（它们支持入口组）。 |
| 隧道型转发组（成员是隧道） | 暂不支持，请用主机型转发组。 |
| 线路组（主备线路、调度） | 共享入站上的规则都不能开线路组。 |
| Shadowsocks 出口 | 不能和共享入站一起用。 |
| 经隧道时的 PROXY Protocol | 经隧道的 SNI 规则不带 PROXY 头（隧道入口在本机回环上，只能看到本机地址）。直连规则、转发链 / 转发组上的规则可以照常往下一跳 / 目标发 PROXY 头。 |
| 保存后换入口方式或走法 | 不支持，请新建规则。 |

## 常见问题

**入站显示「监听失败」？**
端口被这台主机上面板之外的程序占用了（比如主机上自己装的 Nginx 也在听 443）。停掉那个程序或换一个端口。

**连接被直接断开？**
按顺序检查：SNI 是否在入站白名单里；是否有规则认领了这个域名（大小写、`www` 前缀是不同的名字）；那条规则是否在运行；入站是否启用；Agent 版本是否够（直连 2.2.224，经隧道 / 转发链 / 转发组 2.2.255）。经转发组时，还要确认客户端连到的那台入口主机上有同端口的入站。

**转发组没有切到某台成员？**
看组的事件里有没有「共享 TLS 入站未就绪」，原因写在后面：常见的是这台成员上没有同端口的入站、白名单不放行、名字被这台主机上别的规则占了、Agent 低于 2.2.255，或者路由表还没被 Agent 确认（主机详情里显示「路由表待确认」，一般等一次心跳就好）。

**目标服务看到的客户端地址？**
直连时和普通端口转发一样，目标看到的是入口主机的地址；经隧道 / 转发链时看到的是出口（最后一跳）的地址。需要真实客户端地址时，直连规则可以开 PROXY Protocol 发给目标，转发链 / 转发组按资源自己的 PROXY Protocol 设置往下一跳发（经隧道的暂不支持）。

**按来源 IP 的限制管用吗？**
规则自己的入口收到的连接来自本机分流器，按来源 IP 的端口访问限制不作用于共享入站上的规则；连接数、带宽、流量这些按规则的限制照常生效。

**能和隧道、转发组、线路组一起用吗？**
隧道（单入口）、转发链、转发组（主机型）、端口转发资源都可以，需要入口主机 Agent 2.2.255 起。线路组、Shadowsocks 出口、挂了入口组的隧道、隧道型转发组暂不支持，见上面「现在不支持的组合」。
