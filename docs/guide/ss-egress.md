# 落地主机与 Shadowsocks 出口

普通的端口转发是入口机自己去连目标，目标看到的来源 IP 就是入口机。给规则设一个 **Shadowsocks 出口** 之后，入口机不再直接连目标，而是经 Shadowsocks 让另一台服务器（「落地」）代为连接：流量从落地出去，目标看到的是落地的 IP。

```text
客户端 ──▶ 入口机:端口（gost 监听，计数、限速都在这里）
              │  Shadowsocks（加密）
              ▼
          落地 SS 服务器 ──▶ 目标
```

出口有两种来源：

- **落地主机（Shadowsocks）**：面板管理的另一台主机，上面开着一个 Shadowsocks 落地入站（「落地入站」页面里那种 sing-box 节点）。没有的话可以在规则编辑器里 **一键创建**。
- **外部 Shadowsocks 链接**：粘贴一条别处的 `ss://` 链接，例如你在别家买的落地。

::: warning 需要 Agent 2.2.226 或更新版本
出口由 **入口机** 上的 Agent 下发给 gost。入口机的 Agent 低于 2.2.226 时，不能给它的规则设出口；已经设了出口的规则在旧 Agent 上会按停用下发（不会退回直连），规则卡片显示「需要升级 Agent」。落地主机不需要升级。
:::

## 什么时候用它，什么时候用隧道

| | Shadowsocks 出口 | 隧道 |
| --- | --- | --- |
| 落地要装什么 | 落地上只要有一个 Shadowsocks 服务端：面板管的主机一键开，或者用别家的 `ss://` | 落地也必须是面板管理的主机（装 Agent） |
| 能用别家的落地吗 | 能（外部链接） | 不能 |
| 协议 | 目前只有 TCP（见下文 UDP 说明） | TCP / UDP |
| 多出口、负载均衡、线路组 | 不支持，一条规则一个出口 | 支持 |
| 适合 | 「想让目标看到某台机器的 IP」：解锁流媒体、固定出口 IP、借用现成的 SS 落地 | 加密中转、多跳、多出口、要 UDP 的业务 |

已经有隧道的规则不需要再设出口：隧道的出口本身就是落地，二者选一个。

## 在规则里设置出口

在 **转发规则 → 添加 / 编辑规则** 里，选「端口转发」之后，表单里有一节 **出口**：

| 选项 | 说明 |
| --- | --- |
| 直接连接 | 默认。入口机自己连目标 |
| 落地主机 | 选一台落地主机，再选它上面的 Shadowsocks 入站 |
| 外部 SS 链接 | 粘贴 `ss://` 链接 |

选了出口之后，表单会自动做这几件事（因为出口是 gost 的转发链实现的）：

- **转发工具固定为 gost**。用「端口转发」资源时，资源自己的工具必须是 gost，否则出口这一节不能选。
- **协议固定为 TCP**。
- **线路组关闭**：出口本身就是固定的落地。

保存时面板会检查：

- 落地主机要在线（只在新选 / 换落地时检查；已经设好的规则改名字不受影响）；
- 落地主机不能是这条规则的入口主机（包括端口转发资源里的每一台入口）；
- 落地入站必须是 Shadowsocks、启用着、加密方式能做出口；
- 外部链接里的服务器不能是入口主机自己。

规则卡片上会显示 **「经 落地主机 东京 出口」** 或 **「经 外部 SS 出口」**，后面跟状态：

| 状态 | 意思 |
| --- | --- |
| 运行 | 出口配置正常，已下发 |
| 落地离线 | 落地主机的 Agent 掉线了。规则照样下发（落地上的 Shadowsocks 可能还活着），但请检查落地 |
| 需要升级 Agent | 入口机的 Agent 低于 2.2.226，规则没有下发 |
| 落地入站已删除 / 已停用 | 出口用的入站没了或被停用，规则没有下发 |
| 加密方式不支持 | 入站或链接的加密方式不能做出口，规则没有下发 |
| 出口配置失效 | 例如外部链接无法解密（面板迁移到了新服务器），请重新粘贴链接 |

## 一键创建落地 SS 入站

选了落地主机、而它上面还没有能做出口的 Shadowsocks 入站时，出口一节会出现 **「一键创建落地 SS 入站」**：

- 加密方式 `aes-256-gcm`，随机密码；
- 端口从落地主机的端口范围里挑一个空闲的（没设范围时在 20000-30000 之间挑）；
- 走的是「落地入站」页面的同一条新建流程：权限、额度、端口冲突检查一样不少；
- 打上「落地出口」标记：**它派生的节点默认不进客户端订阅**。管理员想把它也给客户端用，在订阅里打开这个节点即可。

谁能一键创建：管理员，或者这台主机的主人（还需要有客户端订阅权限）。

谁能拿落地入站当出口：

- 管理员：任意 Shadowsocks 落地入站；
- 普通用户：自己的落地入站；或者管理员开的「落地出口」入站，并且有这台落地主机的使用权限（和直连规则同一套主机授权）。别人的普通落地节点不能用 —— 那个端口的流量记在它的主人头上。

落地入站 **轮换密码、改端口** 之后，依赖它的规则自动跟上（每次下发都从入站现取凭据），入口机会被立刻通知重算。正在被当作出口的入站 **不能删除**，也不能改成别的协议或出口不支持的加密方式：面板会列出依赖它的规则，请先把这些规则的出口改掉。

## 外部 Shadowsocks 链接

支持 SIP002（`ss://base64(方法:密码)@主机:端口#名字`）和老式的整段 base64 两种写法。

- 加密方式只支持 `aes-256-gcm`、`aes-128-gcm`、`chacha20-ietf-poly1305`（见下文为什么不支持 SS2022）；
- 不支持带插件（`plugin=obfs-local`、`v2ray-plugin` 等）或带 ws / grpc 传输的链接；
- 普通用户可以在自己的规则上使用外部链接；目标地址的限制和普通规则一样（内网 / 环回目标要求入口主机是自己的）。经别人的落地主机出口时，目标还必须是公网地址。

::: danger 安全提示：链接里的密码由面板保存
外部链接解析后的服务器、加密方式和 **密码** 会保存在面板的数据库里，用面板密钥（`JWT_SECRET` 或数据目录里的 `jwt.secret`）派生的 AES-256-GCM 加密，界面上只显示打码后的样子（`ss://aes-256-gcm:******@主机:端口`），接口也从不返回密文。数据库被拖走时拿到的只是密文；但能接触到面板密钥的人（服务器管理员）可以解出密码。不要粘贴你不愿意交给面板管理员的链接。

面板迁移到另一台服务器、且两边的面板密钥不同时，旧密文解不开，规则会显示「出口配置失效」并按停用下发，重新粘贴一次链接即可。
:::

## UDP 和 SS2022 说明

出口用的是随 Agent 下发的 gost 运行时（gost 3.2.6）里的 Shadowsocks 客户端。我们拿它对着落地入站用的 sing-box 1.14.0 逐项实测过：

| | TCP | UDP |
| --- | --- | --- |
| `aes-128-gcm` / `aes-256-gcm` / `chacha20-ietf-poly1305` | 互通 | **不通**（gost 解不出回包） |
| SS2022（`2022-blake3-*`） | **不通**（gost 和 sing-box 的实现不互通） | **不通** |

所以目前：

- 出口 **只转 TCP**，规则协议固定为 TCP，「UDP 也走出口」暂时不能勾。不会出现「TCP 走出口、UDP 偷偷直连」的情况；
- 出口 **不支持 SS2022**。已有的 SS2022 落地入站在出口选择器里会标「不支持做出口」，一键创建的落地入站默认用 `aes-256-gcm`。

老式 AEAD 有已知的主动探测手段，SS2022 在这方面更好；如果落地需要直接给客户端用，仍然建议给客户端另开一个 SS2022 入站。等 gost 运行时升级到能和 sing-box 互通的版本后，面板会放开 UDP 和 SS2022。

## 流量、计费和限速

- **规则的流量统计、按量计费、限速和普通 gost 规则完全一样**：计数挂在入口机的监听端口上，限速是 gost 服务上的限速器，都在入口这一侧。
- 落地主机那边：一键创建的落地入站有自己的端口流量统计（「落地入站」页），经出口的流量也会记在那里；落地主机的机房流量当然也会增加。
- 入口机到落地这一段是 Shadowsocks 加密的；落地到目标这一段和直连一样是明文（目标本身是 HTTPS 的话照样是 HTTPS）。

## 排障

| 现象 | 处理 |
| --- | --- |
| 卡片显示「需要升级 Agent」 | 在主机列表里升级入口机的 Agent 到 2.2.226 或更新 |
| 卡片显示「落地离线」 | 检查落地主机的 Agent 和网络；Shadowsocks 服务本身可能还在跑 |
| 规则运行但连不上目标 | 检查落地主机的防火墙 / 安全组是否放行了落地入站的 TCP 端口；在落地上确认它能访问目标 |
| 删除落地入站时报错 | 报错里列出了依赖它的规则，把这些规则的出口改成其他方式或删掉规则 |
| 外部链接报「不支持」 | 换一条用 `aes-256-gcm` / `aes-128-gcm` / `chacha20-ietf-poly1305`、不带插件的链接 |
