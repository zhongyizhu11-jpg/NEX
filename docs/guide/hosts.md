# 主机管理

主机管理用于查看和维护所有已接入的 Agent 主机。

## 主机列表

主机列表展示每台主机的实时状态，包括：

- **在线/离线状态** — 绿色表示在线，红色表示离线。
- **延迟** — 面板与 Agent 之间的往返延迟，反映连接质量。
- **Agent 版本** — 当前运行的 Agent 版本号。
- **CPU、内存、磁盘占用** — 主机资源使用情况。
- **系统负载** — 系统平均负载。
- **公网 IPv4 / IPv6** — Agent 检测到的公网地址。
- **内网 IP** — 主机内网地址。
- **网卡信息** — 网络接口列表。
- **转发状态** — 当前转发规则的运行情况。
- **流量数据** — 累计上下行流量统计。

## 在线与离线

绿色表示在线，红色表示离线。

如果主机离线，常见原因：

- Agent 服务没有运行。
- Agent 配置中的面板地址不对。
- 面板域名、端口或反向代理不可访问。
- 服务器防火墙阻止连接。
- 面板公开地址修改后，Agent 还在使用旧地址。

在 Agent 主机上可以查看日志排查：

```bash
journalctl -u forwardx-agent -n 300 --no-pager
```

Agent 配置文件位于 `/etc/forwardx/agent/config.json`，日志目录位于 `/var/log/forwardx-agent/`。

## 主机信息维护

建议给每台主机填写清晰的名称，例如：

```text
香港入口-1
日本落地-1
美国中转-1
```

也可以设置：

- **备注** — 记录主机用途或额外说明。
- **手动入口 IP 或域名** — 覆盖自动检测的公网地址。
- **DDNS 域名** — 绑定动态域名，支持 DDNS 故障转移。
- **网卡名称** — 指定流量统计所使用的网卡。

主机名越清楚，后续创建转发规则、隧道和链路时越不容易选错。

## 公网出口整形

机房给机器的公网带宽（比如 500M）是个限速器：超过就丢包。一台机器往客户端发的下载、往目标发的上传都从这里出去，几条 TCP 流一起跑时在限速器上互相挤，吞吐在三四百兆上下锯齿，到不了标称值。公网出口整形让这台机器上的 NEX 把往客户端、往目标发的所有明文流量合起来压在上限之下：限速器不丢包，没有重传和回退，多少条连接合计都贴着上限跑，而且稳。只对 NEX（`forwardx`）隧道的流量生效。

在「编辑主机 → 其他配置」里选：

- **关**（默认）— 不整形。客户端来自四面八方，随机丢包不该让整台机器减速，所以默认关；只在确定有公网限速器的机器上打开。
- **自动** — 由 NEX 自己识别限速点：大流量跑起来、重传率超过 1% 加积压，一秒内开始整形，几秒内学到上限并记住（本机一份、面板一份）。编辑框里能看到当前状态；主机卡片上整形生效时有一行「公网出口整形：488 Mbit/s」。
- **手动** — 填机器的公网带宽（Mbit/s），按它的 96% 起步，之后按重传率在 60% 到 100% 之间自动微调。

整形器只能让这台机器稳稳贴着它的公网带宽跑，不能超过机房卖的带宽；要更高的持续速率，只能换带宽更大的机器，或者把客户端分散到几台入口上。隧道两端之间的专线（比如云联网）另有「链路整形」，见[隧道](./tunnels.md#链路整形)。

## 主机分配给用户

可以将主机分配给指定用户，限制其只能使用授权主机上的资源：

- 进入主机详情，在「分配用户」中选择目标用户。
- 未分配主机的用户在创建转发规则或隧道时看不到该主机。
- 管理员始终可以访问全部主机，不受分配限制。

结合套餐计费和用户权限，可以实现多租户隔离。

## 主机排序

主机管理中的排序通过拖动完成，不需要手动填写排序数字。

- **无分组时** — 在主机列表中直接拖动调整顺序。
- **有分组时** — 「全部」视图按分组顺序汇总展示，不支持直接拖动。切换到具体分组后，只调整该分组内的主机顺序。
- 主机分组、Agent Token 和主机探测服务也支持拖动排序。

## mimic 环境检测

mimic 是基于 eBPF 的 UDP 混淆方案（来自 [hack3ric/mimic](https://github.com/hack3ric/mimic)，GPL-2.0-only，当前版本 v0.7.1），需要 Linux 6.1+ 内核和能编译内核模块的头文件。Agent 每次心跳检测 mimic 命令和内核模块，结果在 **主机详情 › mimic UDP 混淆** 里：

| 状态 | 含义 | 怎么办 |
|------|------|------|
| 就绪 · vX.Y.Z | 命令和内核模块都在，可以开 mimic | — |
| 未安装 | 机器上没有 `mimic` 命令 | 点「安装 mimic」 |
| 内核模块缺失 | 命令在、当前内核没有模块（多半是内核升级后 DKMS 没重编，或缺 `linux-headers-$(uname -r)`） | Agent 会先自己试 `dkms autoinstall`；不行就点「修复 mimic」，日志里会写明缺什么 |
| 内核模块加载失败 | 模块编出来了但 `modprobe` 失败（Secure Boot / MOK 签名等） | 看日志，按提示处理后点「修复」 |
| 系统不支持 | 非 Linux | — |
| 未检测 | Agent 版本过旧或还没上报 | 升级 Agent |

一键安装 / 修复需要 Agent 2.2.223 以上：面板把安装脚本下发给 Agent 在机器上跑（Debian / Ubuntu 用上游预编译包，其它发行版源码编译），每几秒回传进度，装完重新检测。隧道编辑里开 mimic 时也会按参与主机列出同样的状态和按钮。Agent 会在 XDP `native` 与 `skb` 模式之间自动回退，无需在面板手动切换。

## IPv6 检测

如果 IPv6 地址检测不到，先确认服务器自身是否有可用 IPv6：

```bash
ip -6 addr show scope global
ip -6 route
ping -6 -c 4 2606:4700:4700::1111
```

如果服务器只有内网 IPv6 或 IPv6 不可出站，面板可能无法将其作为可用入口展示。

## 流媒体 / AI 解锁检测

**主机详情 › 流媒体 / AI 解锁** 告诉你这台机器的出口 IP 能不能看 Netflix、Disney+、YouTube Premium、TikTok，能不能用 ChatGPT、Claude、Gemini、Grok、Perplexity。需要 Agent 2.2.225 以上，旧 Agent 会显示「需要升级 Agent」。

- **怎么跑** — 管理员点「检测解锁」，Agent 从这台机器自己的出口（不走代理）去打开各服务的页面，十几秒内出结果。上面的「自动 / IPv4 / IPv6」选用哪个协议栈的出口：同一台机器 v4 和 v6 的解锁情况经常不一样，两边分开存、分开看。机器没有 IPv6 出口时，IPv6 检测会全部是「无法判断 · 网络不可达」。
- **默认不定期跑** — 每次检测都要从主机向这些第三方服务发一串请求。需要的话在同一处打开「计划检测」（每天 / 每周，对所有主机生效）：面板每 30 分钟看一次哪些在线主机到期了，每次最多排 20 台，把请求摊开。
- **谁能看** — 能使用这台主机的用户都能看到结果；发起检测和计划检测只有管理员能改。
- **历史** — 每台主机保留最近 10 次（每个协议栈最新的那一次一定留着），点「历史」查看。测过的主机，卡片上会多一行摘要，例如「NF 全解 · GPT ✓ · Claude ✗」。

每一项只有四种结论：

| 结论 | 颜色 | 含义 |
|------|------|------|
| 可用 | 绿 | 页面正常打开、没有地区限制的标记。Netflix 是「全解锁」：非自制剧也能看 |
| 部分可用 | 黄 | Netflix 只能看自制剧；ChatGPT 只有网页能用（App 认为是 VPN）或只有 App 能用（API 不支持这个地区） |
| 不可用 | 红 | 跳到了「这个地区不提供服务」的页面、页面里写着不支持这个地区，或者 IP 被直接拒绝（403） |
| 无法判断 | 灰 | 请求失败、超时，被 Cloudflare 人机验证拦下，或者页面和预期不一样 |

各服务怎么判断（照着社区常用的检测脚本做）：

| 服务 | 方法 |
|------|------|
| Netflix | 打开两部非自制剧和一部自制剧的页面，看是不是「Oh no!」；地区取跳转后的地区路径或页面里的国家 |
| Disney+ | 打开首页，跳到 unavailable / preview 页算不可用；地区按跳转后的语言路径推断。只看首页，不验证能否播放 |
| YouTube Premium | 打开 /premium，看有没有「Premium is not available in your country」，地区取页面里的 GL |
| TikTok | 首页里的 region 字段 |
| ChatGPT | `api.openai.com/compliance/cookie_requirements` 有没有 unsupported_country、`ios.chat.openai.com` 有没有 VPN 提示；地区取 `chatgpt.com/cdn-cgi/trace` |
| Claude | `claude.ai` 会不会跳到 app-unavailable-in-region；地区取 `claude.ai/cdn-cgi/trace` |
| Gemini | 首页里的可用开关；地区是页面里的三字母国家码 |
| Grok / Perplexity | 首页是正常打开、地区封锁页，还是人机验证页；地区取同站的 `/cdn-cgi/trace` |

::: warning 结果是推断，不是保证
这些服务没有公开的「这个 IP 能不能用」接口，检测靠的是页面上的标记。服务一改版，标记就可能失效，结论会变成「无法判断」甚至判错；Disney+、Grok、Perplexity 只看首页，不代表能正常播放或登录使用。拿不准时以实际使用为准。
:::

检测会从这台主机向上述服务（netflix.com、disneyplus.com、youtube.com、tiktok.com、openai.com、chatgpt.com、claude.ai、gemini.google.com、grok.com、perplexity.ai）发起普通的网页请求，每个请求 10 秒超时、最多跟 5 次跳转，不登录、不提交任何账号信息。
