# 主机管理

主机管理用于查看和维护所有已接入的 Agent 主机。

## 主机列表

主机列表展示每台主机的实时状态，包括：

- **在线/离线状态** — 绿色表示在线，红色表示离线。
- **延迟** — 面板与 Agent 之间的往返延迟，反映连接质量。
- **Agent 版本** — 当前运行的 Agent 版本号。
- **CPU、内存、磁盘占用** — 主机资源使用情况。
- **系统负载** — 1 / 5 / 15 分钟平均负载，例如 `0.12 / 0.25 / 0.38`（Linux 的 `/proc/loadavg`，不是百分比：到 CPU 核数才算满）。标准卡片写在 CPU 下面，精简卡片和深空主题的一行视图悬停 CPU 查看，列表视图写在地区、地址下面（精简布局的条状列表同样悬停 CPU），主机详情和公开探针页也有。需要 Agent 2.2.255 以上；老 Agent、没有 `/proc/loadavg` 的系统不报，也就什么都不多显示。只用来看，不参与线路评分（线路评分用的「主机负载」是 CPU 和带宽占用取大的 0–100 分，和这三个数不是一回事）。
- **系统负载** — 系统平均负载。
- **公网 IPv4 / IPv6** — Agent 检测到的公网地址。
- **内网 IP** — 主机内网地址。
- **网卡信息** — 网络接口列表。
- **转发状态** — 当前转发规则的运行情况。
- **流量数据** — 累计上下行流量统计。

## 在线与离线

绿色表示在线，红色表示离线。

如果主机离线，常见原因：

- Agent 服务没有运行。
- Agent 配置中的面板地址不对。
- 面板域名、端口或反向代理不可访问。
- 服务器防火墙阻止连接。
- 面板公开地址修改后，Agent 还在使用旧地址。

在 Agent 主机上可以查看日志排查：

```bash
journalctl -u forwardx-agent -n 300 --no-pager
```

Agent 配置文件位于 `/etc/forwardx/agent/config.json`，日志目录位于 `/var/log/forwardx-agent/`。

## 主机信息维护

建议给每台主机填写清晰的名称，例如：

```text
香港入口-1
日本落地-1
美国中转-1
```

也可以设置：

- **备注** — 记录主机用途或额外说明。
- **手动入口 IP 或域名** — 覆盖自动检测的公网地址。
- **DDNS 域名** — 绑定动态域名，支持 DDNS 故障转移。
- **网卡名称** — 指定流量统计所使用的网卡。

主机名越清楚，后续创建转发规则、隧道和链路时越不容易选错。

## Agent 连接与保护

「编辑主机 → 其他配置」最下面的「Agent 连接与保护」只有管理员能看到，**单独保存**（点这一块里的「保存这几项」），不跟着主机表单的「保存」走。

### Agent 面板连接地址 {#agent-panel-url}

默认所有 Agent 都连系统设置里的「面板公开地址」。有的机器走不通那个地址（国内线路、出站端口受限、要经另一层反代），可以给这台主机单独填一个**反代到同一面板**的 HTTP / HTTPS 地址（可以带端口和路径前缀，不能带账号密码和查询参数）：

- 这台主机的安装命令、升级命令都改用这个地址（Token 管理的「安装命令」里会多一个「主机独立地址」选项并默认选中）；
- 在线的 Agent 不用重装：面板在心跳里把新地址告诉它，Agent **先用自己的 Token 对新地址做一次认证探测**，通了才切换并写进配置；不通就继续用原来的地址，过几分钟再试。切过去之后如果紧接着连续连不上，而原地址还能通过探测，会自动切回原地址。
- 在线切换需要 Agent 2.2.255 以上；更旧的 Agent 会继续用原来的地址（它们收到地址不验证就切，所以面板不发给它们），可以用新地址重新执行安装命令。
- 关掉这一项后，面板改回下发全局「面板公开地址」，Agent 同样验证后切回去；没有配置全局公开地址时 Agent 停留在当前地址。
- 面板迁移进行中时一律下发全局地址，迁移有自己的切换和回退流程。

### 流量阈值关机 {#traffic-shutdown}

**默认关闭，只有管理员能开。** 打开后，这台主机本周期（上一次流量重置之后）已用流量达到套餐流量的设定比例（1%–100%，默认 100%）时，Agent 执行 `systemctl poweroff` / `shutdown -h now` / `poweroff` **关闭整台机器** —— 机器上所有服务都会中断，不只是停止转发；关机不等故障转移，也不等 DDNS 切换。面板不会自动开机，需要在服务商控制台手动开机。开启时会弹窗再确认一次。

- 需要先设置大于 0 的套餐流量；用量口径和主机卡片一样（系统网卡计数，按「流量计算」方式）。
- 只支持以 root 运行的 Linux Agent，且 Agent 2.2.255 以上；不满足时这一块会显示原因，不会下发。
- 执行前面板用最新的开关、额度、比例和最近 10 分钟内上报的计数再判一遍，**同一个流量周期只授权一次**，并先发通知（Telegram / Discord / 邮件给管理员，记进事件时间线），再下发关机指令。Agent 执行前先在本地 `/var/lib/forwardx-agent/traffic-shutdown.json` 记下这个周期，写不进去就不关；机器开回来、面板或 Agent 重启后同一周期都不会再关。
- 流量重置（手动 / 每月自动）换了周期才会重新生效；或者把开关关掉保存、再打开保存，重新布防。只改比例、普通保存不会清掉「本周期已触发」。
- 「本周期已触发」表示已授权执行，不代表确认关机成功。关机命令失败或指令丢失时，为了避免循环关机不会自动重试；查看 Agent 日志里的 `[HostTrafficShutdown]`，排除问题后重新开关。
- 这是依赖面板连接和 Agent 上报的检测，不是断网时的本地硬限制，不能保证精确卡在阈值处。

### 同 Token 换机接管 {#agent-takeover}

Agent 第一次启动时生成一个**安装实例 ID**（存在 `/etc/forwardx/agent/installation.json`），面板记着每台主机当前是哪个实例在管理。拿同一个 Token 的安装命令在**另一台机器**上安装时：

- 新机器上的 Agent 接管这条主机记录（规则、配置会重新下发到新机器），事件时间线记一条「接管」；
- 原来那台机器的 Agent 收到「已被接管」后**停止和面板同步**（不再心跳、不再上报、不再接收配置），本机已有的转发保留，日志里只记一次；
- Token 绑着的主机还在线时，复制安装命令会先确认一次「这台主机已经有在线的 Agent，在另一台机器上安装会接管它」。

升级、同一台机器上重装只要 `installation.json` 还在，实例 ID 不变，不算换机。还没升级、不带实例 ID 的旧版 Agent 照旧工作；但主机一旦被新版 Agent 登记过实例，不带实例 ID 的旧 Agent 再上报会被拒绝（防止旧机器和新机器抢）。旧机器上 FXP 隧道运行时直接上报的流量不受影响。

要把主机换回原来那台机器：先停掉现在这台机器上的 Agent，在「Agent 安装实例」点「解除绑定」，再重启原机器上的 Agent（`systemctl restart forwardx-agent`）。

## 账本 {#ledger}

「主机管理」顶上的「账本」页签（只有管理员能看）把每台机器的钱、到期和流量摆在一张表里：手机上一行一台，电脑上是表格。顶上三个数：

- **每月成本** — 所有填了费用的机器折到每月后的合计。不同币种分开列，不换算（面板没有汇率）；含 95 估算时会注明。
- **30 天内到期** — 到期时间在 30 天以内的台数；已经过期还没续的另外列出来。
- **流量快用完** — 剩余流量低于「流量耗尽提醒」的阈值（默认 20%）、已经用超，或者按这个周期到目前的速度到周期末会超的台数。

每一行有：每月多少钱、几天后到期（7 天以内或提醒天数以内标黄，已过期标红）、本周期已用 / 额度、按当前速度到周期末预计用多少（会超的标红，并写出大约哪天用完）、平均每天还能用多少，以及 95 计费的机器的 95 值估算。

### 填费用

在「编辑主机 → 其他配置」里，账单周期下面有一行「费用」，默认收起，点开填：

- **每期费用** — 填账单上一期的钱，比如季付就填一季多少；账本按账单周期折成每月（季付 ÷ 3、年付 ÷ 12）。币种支持人民币、美元、欧元、港币、日元、英镑。不填就是没算进成本。
- **带宽计费** — 默认「只有固定费用」。机房另按 95 值收带宽费的，选「另按 95 值计费」并填单价（每 Mbps 每月）；每月成本 = 固定费用 + 95 值 × 单价。

### 本周期和预计用量怎么算

- 开了「自动重置流量」的机器，按每月重置日切周期（29、30、31 日在小月按月末算）；周期中间手动清过零的，从清零那一刻起算。
- 没开的机器，从计数器上次清零起算，周期末用机器停止时间；两样都没有就不给预计用量。
- 预计用量 = 已用 ÷ 已过时间 × 整个周期。周期才过不到一天时会标「粗估」。
- 已用量和主机卡片、流量提醒、流量故障转移是同一个数（系统网卡计数，按「流量计算」选的出向 / 双向 / 取最大值）。

### 95 值估算

- 选了「另按 95 值计费」之后，面板才开始给这台记录：每 5 分钟一个点，记这 5 分钟里出、入两个方向较大的那个速率，留 40 天。别的机器不记，没有任何开销。
- 计费周期按「账单日」切月。95 值 = 本周期所有 5 分钟点去掉最高的 5% 之后的最大值。
- 周期没走完之前，这个数只是「到今天为止」的 95 值，所以一律写「估算」。下面几种情况再加「样本不足」：还没有采样、样本不到一天、或者这个周期里缺了一成以上的点（比如月中才改成 95 计费、机器掉线了几天）。
- 两次心跳隔了 15 分钟以上的那段不计入（不知道流量是什么时候跑的，硬摊会造出假峰值）；面板重启会丢掉当时还没走完的那 5 分钟。
- 面板记的是 Agent 报上来的网卡计数，和机房的计量点、取样时刻不完全一样，月底以机房账单为准。

账本只读这些数，不改任何东西：到期提醒、流量自动重置、流量故障转移照原样工作。开了「周期顺延」的机器过了停止时间、还没被顺延的那一会儿，账本按同样的规则显示下一期的到期日。

## 公网出口整形

机房给机器的公网带宽（比如 500M）是个限速器：超过就丢包。一台机器往客户端发的下载、往目标发的上传都从这里出去，几条 TCP 流一起跑时在限速器上互相挤，吞吐在三四百兆上下锯齿，到不了标称值。公网出口整形让这台机器上的 NEX 把往客户端、往目标发的所有明文流量合起来压在上限之下：限速器不丢包，没有重传和回退，多少条连接合计都贴着上限跑，而且稳。只对 NEX（`forwardx`）隧道的流量生效。

在「编辑主机 → 其他配置」里选：

- **关**（默认）— 不整形。客户端来自四面八方，随机丢包不该让整台机器减速，所以默认关；只在确定有公网限速器的机器上打开。
- **自动** — 由 NEX 自己识别限速点：大流量跑起来、重传率超过 1% 加积压，一秒内开始整形，几秒内学到上限并记住（本机一份、面板一份）。编辑框里能看到当前状态；主机卡片上整形生效时有一行「公网出口整形：488 Mbit/s」。
- **手动** — 填机器的公网带宽（Mbit/s），按它的 96% 起步，之后按重传率在 60% 到 100% 之间自动微调。

整形器只能让这台机器稳稳贴着它的公网带宽跑，不能超过机房卖的带宽；要更高的持续速率，只能换带宽更大的机器，或者把客户端分散到几台入口上。隧道两端之间的专线（比如云联网）另有「链路整形」，见[隧道](./tunnels.md#链路整形)。

## 主机分配给用户

可以将主机分配给指定用户，限制其只能使用授权主机上的资源：

- 进入主机详情，在「分配用户」中选择目标用户。
- 未分配主机的用户在创建转发规则或隧道时看不到该主机。
- 管理员始终可以访问全部主机，不受分配限制。

结合套餐计费和用户权限，可以实现多租户隔离。

## 换一台主机 {#replace-host}

旧机到期、被墙、或者想换个更好的机房时，不用一条条改规则：在主机管理里点旧机的「⋯ → 替换到另一台主机」，选新机，看一眼会搬什么，确认后一次搬完。只有管理员能用。

**先把新机接进面板**：装好 Agent、等它显示在线。新机不在线时预览会直接拦住。

### 会自动搬的

| 类别 | 怎么搬 |
| --- | --- |
| 直连规则 | 入口换成新机，端口不变 |
| 隧道 | 入口 / 出口 / 中转 / 额外出口里是旧机的那一端换成新机，隧道上的规则一起走；隧道内部端口在新机上被占会自动换 |
| 转发组成员 | 成员换成新机，组同步在新机上重建子规则；入口组的域名、用到出口组的隧道自动刷新 |
| 线路组中转 | 路径和线路里的旧机换成新机，中继规则按路径重新同步（中转端口自动挑） |
| 节点池（中转） | 池里的旧机换成新机，用到池的线路、跟着池的转发组自动重新展开 |
| 分组和授权 | 新机加进旧机所在的主机分组、用户授权和套餐（旧机的保留） |

搬完之后面板给两台机器（和隧道各端）推一次刷新，旧机上对应的监听随之撤掉。旧机本身不删、不停，方便撤回；勾上「搬完把旧机设为维护」就不再被线路和转发组选用。

### 冲突怎么处理

预览会逐条列出新机上被占的端口（被别的规则、落地入站、共享入站占着，或者不在新机的端口范围里）。每一条可以选：

- **换成一个空闲端口**（默认）— 客户端要改用新端口；
- **这一项不搬** — 留在旧机上。

新机已经在某条隧道里、已经是某个转发组的成员、或者整组共用的端口在新机上被占，这几种只能跳过。

### 不会自动搬、要自己处理的

预览和完成页都会列出来：

- 落地入站（订阅节点）、SNI 共享入站、落地池：密钥和证书跟着机器，要在新机上重开；
- 旧机上的 DDNS、防火墙策略、整台按量计费、自动换 IP 配置；
- 目标手填成旧机 IP 的规则、手填的订阅节点；
- 面板以外的地方：外部 DNS 指向旧 IP、客户端里写死的旧地址。

### 旧地址的过渡

勾着「旧地址先转到新机」时，搬走的规则会在旧机的老端口上留一条临时桥接，把流量转到新机，客户端不刷新订阅也不会马上断。时长用设置里「换入口桥接」的小时数（设成 0 就没有这一项）。这需要旧机还能用：机器已经被墙、或者已经停机时桥接起不了作用，客户端得尽快换新地址。

### 撤回

执行时面板记一份替换记录（改了哪些、原来是什么），保留 30 天。再打开旧机的「替换到另一台主机」，第一页就有「撤回」。撤回按项来：搬完之后又被改过的、原来的端口在旧机上已经被别的占了的，不会动，撤回完会告诉你是哪几项。

预览之后如果有人改了规则、成员或新机上的端口，执行会被拒绝，要求重新预览 —— 不会照着过时的预览去改。每次执行和撤回都记进配置审计。

## 用户自己加机器

普通用户也能加自己的机器（能加几台由管理员定，按钮上写着已用 / 上限）。入口有两个，打开的是同一个框：

- 「主机管理」右上角的 **添加主机**；
- 「订阅管理 › 我的节点 › 我的机器」里的 **加一台**。

填名字和 IP（或域名）保存后，框里直接换成 **Agent 安装命令**：用 root 连上那台机器整行粘进去执行，装好后机器显示在线。以后再要命令，在「我的机器」里那台机器的 **安装命令**。命令里带着这台机器的 Agent 令牌，别转发给别人。「我的机器」只是快捷入口，底部的「去主机管理看全部」进的是同一批机器。

主机详情有一个能分享的地址：`/hosts?host=<主机 id>`，打开详情时地址栏一直带着它。

## 主机排序

主机管理中的排序通过拖动完成，不需要手动填写排序数字。

- **无分组时** — 在主机列表中直接拖动调整顺序。
- **有分组时** — 「全部」视图按分组顺序汇总展示，不支持直接拖动。切换到具体分组后，只调整该分组内的主机顺序。
- 主机分组、Agent Token 和主机探测服务也支持拖动排序。

## mimic 环境检测

mimic 是基于 eBPF 的 UDP 混淆方案（来自 [hack3ric/mimic](https://github.com/hack3ric/mimic)，GPL-2.0-only，当前版本 v0.7.1），需要 Linux 6.1+ 内核和能编译内核模块的头文件。Agent 每次心跳检测 mimic 命令和内核模块，结果在 **主机详情 › mimic UDP 混淆** 里：

| 状态 | 含义 | 怎么办 |
|------|------|------|
| 就绪 · vX.Y.Z | 命令和内核模块都在，可以开 mimic | — |
| 未安装 | 机器上没有 `mimic` 命令 | 点「安装 mimic」 |
| 内核模块缺失 | 命令在、当前内核没有模块（多半是内核升级后 DKMS 没重编，或缺 `linux-headers-$(uname -r)`） | Agent 会先自己试 `dkms autoinstall`；不行就点「修复 mimic」，日志里会写明缺什么 |
| 内核模块加载失败 | 模块编出来了但 `modprobe` 失败（Secure Boot / MOK 签名等） | 看日志，按提示处理后点「修复」 |
| 系统不支持 | 非 Linux | — |
| 未检测 | Agent 版本过旧或还没上报 | 升级 Agent |

一键安装 / 修复需要 Agent 2.2.223 以上：面板把安装脚本下发给 Agent 在机器上跑（Debian / Ubuntu 用上游预编译包，其它发行版源码编译），每几秒回传进度，装完重新检测。隧道编辑里开 mimic 时也会按参与主机列出同样的状态和按钮。Agent 会在 XDP `native` 与 `skb` 模式之间自动回退，无需在面板手动切换。

## 网络画像

**主机详情 › 网络画像** 回答「这台机器从外面看是什么样」：公网地址和双栈、运营商 / ASN、地区、25 端口能不能出站、IP 在不在邮件黑名单上。主机侧的检测需要 Agent 2.2.226 以上，每 6 小时测一次；管理员可以点「重新检测」让 Agent 立刻测一轮（通常半分钟内出结果）。更旧的 Agent 会显示「需要升级 Agent」，这时只能点「从面板查 DNSBL」，由面板服务器代查黑名单。

| 项目 | 怎么测 | 怎么看 |
|------|------|------|
| 公网 IPv4 / IPv6 | Agent 强制用 IPv4 / IPv6 各请求一次 `ipv4.icanhazip.com` / `ipv6.icanhazip.com`（不通再试 ipify），不走代理 | 「通 · 38 ms」就是这一族能出站，地址是对方看到的出口地址；「不通」悬停看原因。另外会看网卡上有没有全局 IPv6 地址：有地址却不通，多半是路由或防火墙没放行 |
| 双栈 | 由上面两项得出 | 双栈 / 仅 IPv4 / 仅 IPv6 / 都不通 |
| 运营商 / ASN、组织 | 跟地区一起由定位服务给（ipapi.co / ipwho.is，只走 HTTPS），不需要 Agent | 例如「AS13335 · Cloudflare」。换了 IP 会重新查 |
| 25 端口出站 | 连 Gmail、iCloud 的收信服务器的 25 端口（5 秒超时），读到欢迎语就发 `QUIT` 断开，**不发任何邮件命令** | 可出站 / 被拦截（连接被拒绝或重置）/ 超时（多半被封） |
| DNSBL 黑名单 | 用主机自己的系统解析器查公网 IPv4 在 Spamhaus ZEN、SpamCop、Barracuda、CBL 里的记录 | 未列入 / 列入 N 个列表（列出名字）/ 无法查询 |

「详细结果」里有每台邮件服务器、每个黑名单的原始结果。

### IP 信息：原生 / 广播、IP 类型、风险

网络画像下面的 **IP 信息** 一块（Agent 2.2.255 起）按 IPv4 / IPv6 分开看这台机器的出口 IP：

| 项目 | 从哪来 | 怎么看 |
|------|------|------|
| IP、ASN / 组织、位置 | ipapi.is、IPinfo、proxycheck.io（依次取第一家给了的） | 和上面「运营商 / ASN」来源不同，偶尔会不一致，以各家数据库为准 |
| 原生 / 广播 | 使用地：各家地理库的国家；注册地：RIPEstat 的 RIR 分配记录（拿不到时退到 ipapi.is 的 ASN 注册国家，证据较弱） | 两边一致是「原生 IP」，不一致是「广播 IP」。几家的使用地互相矛盾，或者缺任何一边，显示「待确认」。下面一行列出用到的每条证据 |
| IP 类型 | 每家各自的分类（ipapi.is、IPinfo 付费字段、proxycheck、AbuseIPDB），归成 家宽 / 机房 / 商业 / 移动 / 教育 / 政府 / CDN | 各家口径不同，逐家列出、不合并；悬停看原始写法 |
| 风险 | proxycheck.io 的 0~100 风险分（免 Key）、ipapi.is 的滥用分（折成 0~100）、配了 Key 时的 AbuseIPDB 滥用置信度 | 0~33 低、34~66 中、67~100 高。各家分别打分，不取平均；另外列出代理 / VPN / Tor / 机房标记 |

- **谁去查**：不要 Key 的 ipapi.is、IPinfo、proxycheck.io 由 Agent **从这台机器自己的出口**去查（免费额度按查询方 IP 算，各台主机互不挤占；IPv6 也只有主机自己出得去），原始响应交回面板解读。RIPEstat 和配了 Key 的几家由面板带着主机的 IP 去查（经面板的出站限制，8 秒超时、64KB 上限）。Agent 低于 2.2.255 时，不要 Key 的几家也由面板代查，查的是面板记录的地址。
- **多久查一次**：每家每个协议族的结果缓存一天（失败的半小时后可重试），随网络画像的 6 小时检测顺带补查；点「重新检测」会全部重查。打开主机详情只读缓存，从不等第三方。
- **查不到**：显示「暂不可用（原因）」，比如「被限流（HTTP 429）」「请求超时」「从主机出口请求失败：网络不可达」。这不是结论，也不会拿别家的数顶上。
- **可选 API Key**（管理员，IP 信息右上角「API Key」）：ipapi.is、AbuseIPDB、IPinfo 三家可以各填一个 Key。Key 加密保存在面板里、只由面板服务器使用，不下发给 Agent，设置页只显示末四位。不填就不调用 AbuseIPDB；ipapi.is、IPinfo 不填时照样由 Agent 免 Key 查。

::: warning 数据库也会错
这些都是第三方 IP 数据库的判断：同一个 IP 在不同库里的国家、类型可能不一样，机房 IP 被标成家宽、广播 IP 被认成原生都时有发生。「原生 / 广播」只说明使用地和注册地是否一致，不代表流媒体一定按哪边认。
:::

### 探测的地址族

「网络测试」的 TCPing 和「服务」里的主机探测服务都可以选地址族：**自动**（照旧，解析器给什么用什么）、**仅 IPv4**、**仅 IPv6**。只在目标是域名时有用 —— 双栈域名想分别看 IPv4 和 IPv6 两条路，就各建一条。选了「仅 IPv6」而域名没有 IPv6 地址时，网络测试直接报错，探测服务记为不通，不会悄悄改测另一族。目标本身是 IP 时按 IP 本身。网络测试的地址由面板解析好再下发，所有 Agent 都生效；探测服务由 Agent 解析，需要 Agent 2.2.226 以上，更旧的 Agent 照旧按「自动」。

### URL 连接检测 {#url-probe}

「服务」里新建或编辑服务时，类型除了 Ping、TCPing 还可以选 **URL 连接检测**：填一个完整的 `http://` 或 `https://` 地址、预期状态码（默认 `200-399`，可写单个、区间或逗号分开的几个，例如 `200`、`200,204`、`301-302`）和超时（1–30 秒，默认 5 秒），再选运行的主机和检测间隔。

- 由选中主机的 Agent 每次**新建连接**发一个 `GET`，延迟从开始建连算到收到响应的**第一个字节**（含 HTTPS 握手，不含 DNS 解析，也不等下载内容）；不复用连接、不走系统代理、**不跟随跳转** —— 301 / 302 就是它的状态码，算不算通由预期状态码决定。
- 响应内容一个字节都不读。请求只带 `User-Agent`，不带面板地址、Agent Token 或任何认证信息。URL 不能带账号密码，也别在查询参数里放密钥（地址会下发给 Agent、存在面板库里）。
- HTTPS 默认校验证书：证书过期、域名不符、自签名都算失败。只在测自签名的内网服务时勾「忽略证书错误」。
- 失败分开显示：**HTTP 状态码不符**（连上了，回的状态码不在预期里 —— 对端应用的事）、**证书校验失败**、**连接超时 / 连接被拒 / 解析失败** 等（链路的事）。图表里的失败比例是请求失败率，不是 ICMP 丢包率。
- 需要 **Agent 2.2.255** 以上。面板只把这类服务下发给够版本的 Agent，旧 Agent 不执行（不会退化成 TCPing 误报成功）；服务卡片和服务延迟图表上会写「需要升级 Agent」。
- 结果和 Ping / TCPing 一样进服务延迟图表、按小时汇总、统计卡片（见 [延迟与流量](./traffic-latency.md#latency-stats)）。这是从主机出口直接测，不经过某条转发规则或隧道。请选允许周期性 `GET` 的健康检查地址。

### 为什么 25 端口经常被封

25 端口是服务器之间投递邮件用的端口。云服务商为了防止新开的机器被拿去发垃圾邮件，大多默认在出口封掉它：有的直接拒绝连接（显示「被拦截」），有的静默丢包（显示「超时」）。这只影响**从这台机器直接往外投递邮件**，不影响转发、网站、收邮件（入站 25）或用 465 / 587 端口经邮件服务商发信。确实需要自己投递邮件的，一般要在服务商控制台申请解封。

### DNSBL 列入意味着什么

DNSBL 是邮件服务器用来判断「这个 IP 发来的邮件要不要收」的黑名单。被列入只影响**这台机器直接发出的邮件**（会被退信或进垃圾箱），不影响转发、网站和其他流量。云主机的 IP 经常是别人用过的，列入记录可能是上一任留下的。

- 这一项**只是提示**：面板不会因为列入而停用主机或规则。
- Spamhaus 的返回码：SBL（垃圾邮件来源）、XBL / CBL（中毒或被利用的机器）、PBL（这段地址按策略不该直接发信，云主机和家宽常见，不算「作恶」）。
- 要解除，去对应列表的网站按 IP 查询并申请移除；SpamCop 的记录通常 24 小时内自动过期。
- 「无法查询（公共解析器被拒绝）」：Spamhaus 不回答来自 8.8.8.8、1.1.1.1 这类公共 DNS 的查询，会返回 127.255.255.254 之类的特殊地址。这**不是列入**，只是查不了。主机想自己查，需要用运营商的解析器或自建递归解析。
- 「从面板查 DNSBL」用的是面板服务器的解析器，结果同样受它影响。

## 网络调优

主机详情 › 更多 › **网络调优**（管理员）列出这台机器转发相关的内核参数：拥塞控制和默认队列、缓冲区、连接跟踪、队列、TCP 行为，逐项标出「达标 / 偏低 / 自选 / 没有」。

| 操作 | 说明 | 需要 |
| --- | --- | --- |
| 检查 | 只读，读出现在的值 | Agent 2.2.250 |
| 一键调优 | 按安装脚本那套规则调：只往更适合转发的方向调，已经更好的值保留，自己选的拥塞控制算法不动 | Agent 2.2.250 |
| 逐项设置 | 自己填每一项的值。拥塞控制只能选内核里有的算法，默认队列可选 fq、fq_codel、cake 等；数字参数的段数要和现在一样（TCP 窗口是三段）。写完 Agent 读回来核对，内核没接受的值自动改回原值 | Agent 2.2.255 |
| 还原调优前 | 改回面板第一次改这台机器之前的值，并删掉面板写的 `/etc/sysctl.d/99-forwardx-network.conf` 和 `/etc/modprobe.d/99-forwardx-conntrack.conf` | Agent 2.2.255 |

「TCP 接收窗口」（`net.ipv4.tcp_rmem`，三个数是「最小 起点 上限」）看两段：上限至少 64 MB，起点（每条连接的接收缓冲从多大开始长）至少 1 MB。内核默认的起点是 128 KB，高延迟又丢包的线路上新连接会被它卡住，十几秒都爬不起来；V1、V2、V3 隧道和 gost、realm 这些用户态转发都受它影响。1 MB 只是起点，内核按实际收到的数据分配，没数据进来的连接不多占；对端一直不读的连接最多攒到 1 MB（原来是 128 KB），几千条这样的连接要多占几 GB，小内存机器上会碰到内核的 TCP 内存上限（`net.ipv4.tcp_mem`）。只抬不降：自己调得更大的不动。安装和升级 Agent 时安装脚本会自动补上起点；老版本调过、还没升级的机器在这里显示「偏低」，升级 Agent（2.2.257 起）就好，也可以升级后再点一次一键调优。逐项设置时三个数要从小到大。

调优和逐项设置都立即生效，并写进 `/etc/sysctl.d/99-forwardx-network.conf`，重启后还在。第一次改动之前 Agent 会把当时的值存到 `/etc/forwardx-nettune/backup.json`，之后不再覆盖，所以「还原」回到的始终是面板第一次动手之前的样子。安装 Agent 时脚本自动做的那次调优不算，那一次的原值没有留。

容器里运行的 Agent 改不了宿主机的内核参数，会提示「没有权限改」。

## 多个公网 IP 与主 IP {#multi-ip}

Agent 2.2.255 起，除了出网用的那个地址，还会上报网卡上**真正配着的**全部公网 IPv4 / IPv6（每族最多 16 个）。不算在内的：内网、CGNAT（100.64/10）、链路本地、ULA（fc00::/7）、文档段；docker、网桥、veth、虚拟机、WireGuard / tun 这类接口上的地址；DAD 没过、已废弃、临时（隐私扩展）的 IPv6。

- **主机卡片 / 列表**：地址后面写「+N 个 IP」，悬停看全部，主 IP、出口 IP 标出来。
- **主机详情**：「全部公网 IP」列出每一个地址。
- **编辑主机 › 主 IPv4 / 主 IPv6**：有不止一个候选时可以各挑一个。规则、隧道、订阅、入口地址、DDNS「仅主 IP」都按主 IP 走 —— 它就是原来那个「IPv4 / IPv6」地址，只是由你指定，不再跟着 Agent 的出口走。

几条规则：

- 从没挑过：和以前一模一样，用 Agent 上报的出口地址。
- 挑过的地址从网卡上消失了：**照样用它**，卡片上提示「主 IP 需确认」。不自动换，因为换主 IP 等于悄悄改了所有规则的入口。确认地址已被回收，就换一个或改回「跟随 Agent 上报」。
- 手改了「Agent 检测 IP」：手改的优先，主 IP 的选择先存着不生效；清空手改的地址后恢复。
- 「自动换 IP」换掉的正好是选中的主 IP：会自动取消选择，改用 Agent 上报的新地址。
- 旧 Agent 不报地址列表，这一块不显示，什么都不变。

DDNS 想把全部地址都发出去，见 [DDNS › 主机 DDNS](./ddns.md#host-ddns) 的「全部 IP」。

## IPv6 检测

如果 IPv6 地址检测不到，先确认服务器自身是否有可用 IPv6：

```bash
ip -6 addr show scope global
ip -6 route
ping -6 -c 4 2606:4700:4700::1111
```

如果服务器只有内网 IPv6 或 IPv6 不可出站，面板可能无法将其作为可用入口展示。

## 流媒体 / AI 解锁检测

**主机详情 › 流媒体 / AI 解锁** 告诉你这台机器的出口 IP 能不能看 Netflix、Disney+、YouTube Premium、TikTok、Prime Video，能不能注册 Spotify、Steam 商店是哪个币种、能不能看 Bilibili 港澳台番剧，能不能用 ChatGPT、Claude、Gemini、Grok、Perplexity。需要 Agent 2.2.226 以上；Prime Video、Spotify、Steam、Bilibili 港澳台这四项要 Agent 2.2.255 起，更旧的 Agent 测不了这几项，面板会提示升级而不是显示「检测失败」。

- **怎么跑** — 管理员点「检测 IPv4」/「检测 IPv6」，Agent 从这台机器自己的出口（不走代理）去打开各服务的页面，十几秒内出结果。同一台机器 v4 和 v6 的解锁情况经常不一样，两边分开存、分开看。网络画像测到 IPv4、IPv6 都能出站时多一个 **「检测双栈」**：两个出口各排一次，结果按 IPv4 / IPv6 页签分开看；计划检测对这种主机也自动两个出口分开测。机器没有 IPv6 出口时，IPv6 检测会全部是「检测失败 · 网络不可达」。
- **默认不定期跑** — 每次检测都要从主机向这些第三方服务发一串请求。需要的话在同一处打开「计划检测」（每天 / 每周，对所有主机生效）：面板每 30 分钟看一次哪些在线主机到期了，每次最多排 20 台，把请求摊开。
- **谁能看** — 能使用这台主机的用户都能看到结果；发起检测和计划检测只有管理员能改。
- **历史** — 每台主机保留最近 10 次（每个协议栈最新的那一次一定留着），点「历史」查看。结果只在主机详情里看：这一节默认折叠，点开才显示（主机卡片上不显示解锁摘要）。

每一项只有四种结论，后面跟着服务认的地区：

| 结论 | 颜色 | 含义 |
|------|------|------|
| 解锁 | 绿 | 页面正常打开、没有地区限制的标记。Netflix 是「全解锁」：非自制剧也能看 |
| 仅自制 / 部分解锁 | 黄 | Netflix 只能看自制剧（仅自制）；ChatGPT 只有网页能用（App 认为是 VPN）或只有 App 能用（API 不支持这个地区） |
| 屏蔽 | 红 | 跳到了「这个地区不提供服务」的页面、页面里写着不支持这个地区，或者 IP 被直接拒绝（403） |
| 检测失败 | 灰 | 请求失败、超时，被 Cloudflare 人机验证拦下，或者页面和预期不一样 —— 是没测成，不是结论 |

**地区的颜色**和主机所在地（主机行上的国家）比：一致为绿，跨区为橙，不在中国的机器却被认成 CN 为红（多半是回国线路的出口）。Steam 给的是商店币种（例如「币种 HKD」），按币种对应的国家比；Steam 在不少地区也标美元，那种情况会显示成跨区。

各服务怎么判断（照着社区常用的检测脚本做）：

| 服务 | 方法 |
|------|------|
| Netflix | 打开两部非自制剧和一部自制剧的页面，看是不是「Oh no!」；地区取跳转后的地区路径或页面里的国家 |
| Disney+ | 打开首页，跳到 unavailable / preview 页算不可用；地区按跳转后的语言路径推断。只看首页，不验证能否播放 |
| YouTube Premium | 打开 /premium，看有没有「Premium is not available in your country」，地区取页面里的 GL |
| TikTok | 首页里的 region 字段 |
| ChatGPT | `api.openai.com/compliance/cookie_requirements` 有没有 unsupported_country、`ios.chat.openai.com` 有没有 VPN 提示；地区取 `chatgpt.com/cdn-cgi/trace` |
| Claude | `claude.ai` 会不会跳到 app-unavailable-in-region；地区取 `claude.ai/cdn-cgi/trace` |
| Gemini | 首页里的可用开关；地区是页面里的三字母国家码 |
| Grok / Perplexity | 首页是正常打开、地区封锁页，还是人机验证页；地区取同站的 `/cdn-cgi/trace` |
| Prime Video | 首页里有 `isServiceRestricted` 算屏蔽；地区取页面里的 `currentTerritory` |
| Spotify 注册 | 打开 `spotify.com/signup`，看跳到哪个市场（`/hk-en/signup` → HK）；跳到选择国家的页面或写着不支持这个国家算屏蔽。只看网页跳转，不调用注册接口 |
| Steam 商店 | 一个付费游戏的商店页里的 `priceCurrency`，地区字段写币种 |
| Bilibili 港澳台 | 港澳台限定番剧的 playurl 接口：`code 0` 算解锁，`-10403` 算屏蔽（仅限港澳台），被风控拦下算检测失败 |

::: warning 结果是推断，不是保证
这些服务没有公开的「这个 IP 能不能用」接口，检测靠的是页面上的标记。服务一改版，标记就可能失效，结论会变成「无法判断」甚至判错；Disney+、Grok、Perplexity 只看首页，不代表能正常播放或登录使用。拿不准时以实际使用为准。
:::

检测会从这台主机向上述服务（netflix.com、disneyplus.com、youtube.com、tiktok.com、openai.com、chatgpt.com、claude.ai、gemini.google.com、grok.com、perplexity.ai、primevideo.com、spotify.com、store.steampowered.com、api.bilibili.com）发起普通的网页请求，每个请求 10 秒超时、最多跟 5 次跳转，不登录、不提交任何账号信息。

## 网速测试 {#speed-test}

**主机详情 › 网速测试** 测这台机器自己的带宽。需要 Agent 2.2.241 以上；**2.2.247 起测得准**（大陆的主机要 **2.2.248**，见下面「国内机器」），老 Agent 弹窗里会提示升级（2.2.246 碰到 Ookla 测速点把上传 307 转走就整段失败、退到面板）。

- **测速点怎么挑（2.2.246 起）**：
  1. **就近的 Ookla 测速点**：从 speedtest.net 拿出口附近的几台测速服务器，各 ping 三次，按延迟排。海外机器拿到的是机房附近的。VPS 测带宽的脚本（bench.sh、融合怪）也是这么测的。挑中的那台测不成（回错误码、上传被拒）就换延迟次低的那台从头测，最多试三台，弹窗里写明换过；测速点把请求 307 转到别处（比如 http 转 https）会跟过去。
  2. **Cloudflare**：Ookla 测不了时换它。Cloudflare 对机房出口有限流（HTTP 429）：说几秒后再来就等一下接着测，说要等很久就报出来「约 N 分钟后才放开」，再换下一个。
  3. **面板**：前两个都测不了时才测到面板服务器。这量的是到面板这条路，**上限是面板服务器自己的带宽**（面板是 50M 的口，测出来就到不了 50M 以上），弹窗里写成「到面板的速度」，不代表这台机器的带宽。
- **国内机器（2.2.248 起）**：speedtest.net 在大陆连不上，它的服务器列表又不给境外来的请求列大陆的测速点，以前国内机器只能退到测面板（几台腾讯云广州都是二三十 Mbps，量的是出境到面板那一段）。现在测大陆的主机（主机所在地是中国大陆）时，面板随指令带一份**国内三网的 Ookla 测速点**（上海、江苏、浙江、湖北、湖南、四川、福建、北京、天津的电信 / 联通 / 移动，运营商自己架的），Agent 全 ping 一遍，挑同运营商里延迟最低的测；speedtest.net 只等 5 秒，它给的境外测速点不要（过了墙测出来的是出境那一段，不是这台机器的带宽）。运营商按主机 IP 归属认（腾讯云、阿里云这类多线 BGP 的只按延迟挑）。弹窗里写明「测速点从面板带的国内列表里挑」。这份列表里的测速点下线了 Agent 会跳过；全都连不上才照旧退到 Cloudflare / 面板。
- **怎么量**：延迟是连接建好以后来回一趟（十次取中位数），抖动是相邻两次的差，10 ms 以下留一位小数。下载 10 秒、上传 8 秒，Ookla 八条连接、Cloudflare 和面板四条一起跑，先丢掉前 2 秒（TCP 慢启动），剩下每半秒一格，照 Ookla 的做法丢掉最慢的 30% 和最快的 10% 再平均（2.2.247 起；以前直接平均，起伏大的线路偏低）。国内机器挑测速点时，和它同一家运营商（电信 / 联通 / 移动）、延迟又不比最快的差太多的排前面：跨运营商的互联口常常是瓶颈。
- **上传只算对端收下的（2.2.246 起）**：以前字节一写进本机网卡缓冲就算送出去了，经 sing-box、几跳转发时会先被沿路的缓冲吞下，曲线开头冲到几百上千 Mbps，后面又掉到 0，结果偏高很多。现在每次送多少由测速点回话确认（Ookla 回 `size=`、面板回 `{bytes}`、Cloudflare 回 200），每次送多大跟着速度调到一次 1 秒左右。
- **链路上的速度**：2.3.502–2.3.504 订阅预览里每条线路有「测速」，在入口机上经整条链测；实测下来瓶颈几乎都在入口机自己的带宽（国内机器 200M / 300M 的口），整链测出来的数意义不大，2.3.505 去掉了。机器之间那几段的速度用 **网络测试 › iperf3 对拉**（见[排障 › 隧道带宽跑不满](./troubleshooting.md#隧道带宽跑不满)）。
- **流量**：下载加上传大约是「速度 × 18 秒」，100M 的机器一次 200 多 MB、1G 的机器 2 GB 多，所以不会自动跑。弹窗里会写这次用掉多少。
