# 自动换 IP

转发机的公网 IP 被墙（这台机器连不上中国大陆）时，NEX 可以调用云厂商的接口给它换一个公网 IP，然后让入口地址和 DNS 跟着改，用户这边基本无感。

这个功能由官方插件「NEX 自动换 IP」（`auto-ip-change`）开关：NEX 的插件只是声明文件，不能在面板后端运行代码，而换 IP 需要拿着云账号凭据去调云厂商接口，所以功能写在面板核心里，插件负责打开它、并在侧边栏放一个入口。

## 开启 {#enable}

1. 在「系统设置」里打开**插件功能**总开关。
2. 在「插件管理」的插件商店里安装「NEX 自动换 IP」，然后**启用**它。
3. 侧边栏出现「自动换 IP」入口（地址 `/ip-change`）。不想要这个入口可以在插件管理里把侧边栏入口关掉，功能照常。

插件停用或卸载后：Agent 上的探测任务会撤掉，所有接口和定时任务停止，已保存的云账号和主机配置留在数据库里，重新启用后继续用。

## 配置步骤 {#setup}

### 1. 添加云账号

「云账号」页点「添加云账号」，选云厂商，按表单填写凭据。表单里的字段由各个云厂商自己声明（例如 Access Key、API Token、私钥），每个字段下面的说明会告诉你去哪拿、需要什么权限。建议：

- 单独为 NEX 建一个子账号 / API 令牌，只给「查询实例、申请 / 绑定 / 释放公网 IP」需要的最小权限。
- 保存后点闪电图标「测试」，填一台实例的信息，面板会查一次它当前的公网 IP。测试不会改动任何东西。

凭据加密后保存在面板数据库里（见下方[凭据安全](#secrets)），任何接口都不会把原文返回给浏览器。

### 2. 给主机加配置

「主机」页点「添加主机」：

| 设置 | 说明 |
| --- | --- |
| 云账号 | 选上一步加的账号。不选也可以：只检测、只提醒，不更换。 |
| 实例信息 | 由云厂商声明（地域、实例 ID 等），告诉面板这台主机对应云上的哪台实例。 |
| 启用检测 | 打开后主机的 Agent 开始探测大陆连通性。 |
| 到阈值后自动更换 | 打开后，判定被墙会自动更换；不打开只发通知，由你决定要不要点「立即更换」。 |
| 探测方式 / 目标 | 默认 TCP 连接三家运营商的官网。见下方[怎么判断被墙](#detection)。 |
| 连续失败几轮 | 默认 5 轮。 |
| 检测间隔 | 默认 60 秒，最少 30 秒。 |
| 冷却 | 默认 30 分钟。 |
| 每天最多 | 默认 3 次。 |
| 换完释放旧 IP | 默认打开。见下方[费用提醒](#costs)。 |

卡片右上角的开关可以直接开关「自动更换」。

## 怎么判断被墙 {#detection}

探测由**主机自己的 Agent** 完成：面板通过「主机探测服务」那条现成的通道，在心跳里给这台主机下发几个探测任务（不需要升级 Agent，也不会出现在你自己的探测服务列表里），Agent 定时向这些大陆目标发起 TCP 连接或 ping，结果随延迟上报回面板。

判定规则：

- 一轮里**所有**目标都失败，才算一轮失败。只要有一个目标通，就不是被墙（可能只是某个目标自己挂了），连续失败数清零。
- 主机对面板**离线**时什么都不做：可能是面板这边的网络问题，也可能是机器宕了，换 IP 解决不了，还白花钱。因此面板本身最好部署在大陆以外、或者至少不和被检测的主机走同一条被墙的线路。
- 连续失败达到阈值后：打开了「自动更换」的主机自动更换，没打开的发一次「疑似被墙」通知。
- Agent 的探测周期可能比检测间隔短，面板按时间切轮：距上一轮记账不到检测间隔的 80% 时，失败只先攒着。阈值 5、间隔 60 秒的意思就是「连续大约 5 分钟全部不通」。

::: warning 探测目标要选只在大陆有节点的
`www.qq.com`、`www.baidu.com` 这类大站在海外有 CDN 节点，从境外机器解析出来的是境外 IP，被墙了照样通 —— 而只要有一个目标通就不算被墙，这样的目标会让检测永远不触发。默认用的是三家运营商官网（`www.189.cn`、`www.10086.cn`、`www.10010.com`）。也可以直接写大陆 IP。
:::

## 更换流程和限制 {#flow}

- **一台一台来**：同一台主机同时只会有一次更换，第二个请求直接拒绝。
- **先记账再动手**：调用云厂商之前，面板先把状态记成「正在更换」并写一条记录。面板如果在更换中途重启，启动后会把它改成「结果不确定」，**不会自动重发**（重发一次可能就是又多申请了一个要花钱的 IP）。
- **冷却和每日上限**只约束自动更换：两次更换（无论成败、手动还是自动）之间至少隔冷却时间；过去 24 小时内的更换次数（手动和自动都算）到上限后不再自动更换，并通知一次。
- **立即更换**（手动）需要确认，不看冷却和每日上限，但「正在更换」「结果不确定」时一样拒绝。
- 单次调用最长 15 分钟，超时按「结果不确定」处理。

失败的三种结果：

| 云厂商的回答 | 状态 | 之后 |
| --- | --- | --- |
| 请求可能已经生效 / 超时 / 返回值不对 | 结果不确定 | 自动和手动都停下。请到云控制台确认实例和 IP 的实际情况，再点「重置状态」。 |
| 明确可以稍后重试（如配额、限流） | 冷却中 | 冷却结束后如果仍被墙，自动再试（受每日上限约束）。 |
| 明确失败（如凭据无效、实例不存在） | 出错 | 不再自动重试。修好配置后点「重置状态」。 |

每一次更换（以及云账号测试）都记在「更换记录」里，可以按主机筛选。

## 换完以后地址和 DNS {#dns}

云厂商会说明新 IP 是哪一种：

**主 IP（primary）**：实例自己的公网 IP 变了。

- 主机的 Agent 每分钟检测一次公网 IP，会自己报上新 IP。面板收到后走和平时一样的流程：更新主机 DDNS、规则专属域名、转发组 / 入口组、隧道和转发链的拨号地址。
- 面板不会抢先改主机的 IP（Agent 下一次心跳可能还带着旧 IP，抢写会来回跳），而是等 Agent 报上新 IP 后**再强制刷新一次主机 DDNS**（最多等 5 分钟）。
- 如果这台主机在编辑里**手动锁定了检测 IP**，Agent 上报的地址会被忽略，面板会直接把它改成新 IP，并走上面同样的联动、强制刷新 DDNS。

**入口 IP（entry）**：实例自己的 IP 没变，只是多了一个入口 IP（例如转发型的公网 IP）。

- 面板把主机的**入口地址**改成新 IP，规则、订阅、转发组用的入口跟着改。
- 入口地址原来是自定义域名的不动，只在记录里提醒你把域名解析到新 IP。
- 主机 DDNS 跟随的是 Agent 检测到的 IP，入口型更换不会改它；而规则里 DDNS 域名排在入口 IP 前面。这种主机如果开了主机 DDNS，请关掉它，或改用规则专属域名。

两种情况下，主机的入口地址如果原来手填的正好是旧 IP，都会一起改成新 IP。

## 通知 {#notifications}

- **Telegram**：更换成功、失败 / 结果不确定、疑似被墙（没开自动更换、或被冷却 / 上限 / 状态挡住）都会发给绑定了 Telegram 的管理员，可以在机器人里按「主机上下线」这一类静音。
- **事件时间线 / Webhook**：记成 `host.ip_changed`、`host.ip_change_failed`、`host.ip_blocked_suspected`，属于 Webhook 的「主机」一类。
- 主机详情里有一小块「自动换 IP」状态，可以直接跳到设置页。

## 凭据安全 {#secrets}

- 云账号凭据用 AES-256-GCM 加密后存进数据库，密钥由面板的 Cookie 签名密钥（`JWT_SECRET` 环境变量；没配时是数据目录下自动生成的 `jwt.secret`）派生。数据库或备份文件泄露时拿到的只是密文。
- 密钥类字段只回打码后的值（例如 `AKI******XYZ`）；编辑时不动它就保持原样。
- **迁移到新服务器**：新机器上的 `jwt.secret` 不同，旧密文解不开，云账号页会提示「需要重新填写」；主机配置照常迁移。两边配置同一个 `JWT_SECRET` 时不受影响。切换数据库类型（SQLite → MySQL 等）不受影响。

## 费用提醒 {#costs}

::: danger 换 IP 可能产生费用
- 新申请的弹性 IP / 静态 IP / 预留 IP 在很多云上单独计费，有的按小时收。
- 旧 IP 不释放通常会继续计费（甚至因为「已申请未绑定」收得更多）。「换完释放旧 IP」默认打开；云厂商没能释放时，更换记录里会提示你去控制台确认。
- 有的云换 IP 需要关机或断网一段时间，添加云账号时会提示。
- 冷却时间和每日上限就是为了防止一台机器被反复更换、费用失控。被墙得很频繁的机器，换 IP 往往不是长久之计。
:::

## 常见问题 {#faq}

**「上次检测」一直是「等待 Agent 上报」？** Agent 要在线，并且下一次心跳才会拿到探测任务。插件刚启用时最长需要约半分钟。如果一直没有，检查 Agent 是否在线、版本是否太旧（太旧的 Agent 不支持主机探测服务）。

**为什么状态是「结果不确定」？** 云厂商接口超时、返回了「可能已经生效」，或者面板在更换中途重启。请先到云控制台确认：实例现在的 IP 是什么、有没有多出未绑定的 IP，处理好以后点「重置状态」。

**云厂商列表是空的？** 你使用的面板版本还没有内置云厂商接口。可以先把检测和主机配置设好（只检测、只提醒），升级后再接上云账号。
